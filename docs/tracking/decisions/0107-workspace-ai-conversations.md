# 0107 — 창의 AI 도우미에서 대화를 고르고, 문서 대상은 실행마다 고정한다

## 맥락

사용자는 [작업 화면 개편 계획](../../plans/workspace-ui.md)에 따라 개발을 진행하고, 독립적인 작업은 병렬로 진행하도록 요청했다(2026-11-04). 문서 둘을 좌우/위아래로 보면서 한쪽 자료를 읽어 다른 쪽 문서에 적용하는 것이 대표 작업이다.

사용자가 정한 대화 방식은 창의 AI 패널 하나에서 여러 대화 중 하나를 고르는 것이다. 대화 선택과 문서 탭 선택은 별개이고, 기존 문서별 기록을 자동으로 합치지 않는다. 현재 결정 0037의 화면은 초점을 받은 편집기 패널을 펴고 다른 편집기의 패널을 접는다. 그 배선만으로는 대화·수정 대상·참고 문서를 독립적으로 고르는 공용 패널이 되지 않는다.

## 결정

- **목표 구조는 창마다 AI 패널 하나와 대화 선택기 하나다.** 대화마다 기록·초안·첨부·참고·수정 대상·프로젝트·실행·대기열·허락을 따로 유지한다. 문서 칸을 클릭하거나 대화를 열어 읽는 것만으로 모델 호출·문서 편집·대상 교체·허락 승인이 일어나지 않는다.
- **문서와 AI 도구의 소유를 나눈다.** 저장·인쇄·서식·쪽·셀·슬라이드 같은 수동 문서 기능은 문서 영역에 둔다. 모델을 부르는 작업은 공용 AI 영역으로 옮긴다. 기존 패널이 제공하던 기능을 공용 패널에서 검증하기 전에는 해당 진입점을 먼저 없애지 않는다.
- **실행 대상은 정체와 세대로 고정한다.** 창·탭·문서 인스턴스·편집기 세대와 선택 스냅숏·문서 버전·프로젝트를 `conversationId`/`runId`에 묶는다. main이 발급한 실행 바인딩 번호도 짝지어 늦은 답이 재사용된 id에 붙지 않게 한다. 현재 활성 탭·파일 경로·제목·좌우 배치로 진행 중인 실행의 대상을 다시 찾지 않는다.
- **참고는 읽기 전용, 수정 대상은 한 문서다.** 명시한 참고 문서의 현재 내용을 각 편집기의 검증된 읽기 경로로 얻는다. 요청에 없는 문서나 참고 문서에 대한 쓰기는 거절한다. 가리기·읽기 불가·문서 변경은 기존 보호와 함께 검사하며, 디스크의 예전 사본으로 대신하거나 읽기 위해 자동 저장하지 않는다. 기존 공개 MCP 읽기를 가리기 없는 실시간 참고 경로로 쓰지 않는다.
- **중단·닫기·새로고침·시간 초과는 바인딩을 끝낸다.** 늦은 응답을 새 문서·다른 대화에 전달하지 않는다. 도구 호출은 한 번만 소비하고 편집을 자동 재전송하지 않는다. 호스트의 transport/편집기 취소와 실제 적용 직전의 편집기 검증이 모두 필요하다.
- **기존 보관의 출처를 보존한다.** 문서별 ProjectStore 기록, 프로젝트 폴더의 대화, 홈의 임시 대화를 출처 참조로 구분한다. 기록을 자동 복사·병합·삭제하지 않고, 새 다중 문서 대화를 파일 하나의 경로 해시로 만들지 않는다. 다른 프로젝트 대화를 골라도 지침·첨부·MCP 허락을 자동으로 섞지 않는다.

### 단계적 구현의 기본안

다음 두 항목은 사용자가 별도로 고른 세부 정책이 아니라, 이번 개발을 진행하기 위한 보수적인 기본안이다. 사용자 요구에 따라 이후 바꿀 수 있으며, 바꿀 때 이 결정과 계약을 함께 맞춘다.

- **같은 창의 문서만** 대상·참고로 제공한다. 다른 창 접근은 열지 않고, 떼어 낸 창/독립 편집기의 기존 동작을 유지한다.
- **창마다 실행 하나**, 사람이 보낸 나머지 요청은 실행 당시 대상을 담아 FIFO로 기다린다. 다른 대화의 읽기·초안 작성은 막지 않는다. 대기 중 대상/참고가 바뀌면 다시 검토하게 하며, 이전 요청이 같은 문서를 고쳤을 때도 오래된 선택으로 자동 실행하지 않는다.

## 현재 적용 범위

**이 결정은 목표 구조와 이행 경계를 정한다. 현재 배포 동작에 결정 0037의 AI 배선을 대체 적용한 상태가 아니다.** 이번 변경은 화면 나누기 진입점·독립적인 키보드 조작, 셸 문서 영역의 공간 계산/시제품, IPC에 등록하지 않은 실행 바인딩 모델부터 진행한다. 실제 편집기 어댑터·대화 컨트롤러·영속 보관 연결·공용 패널은 별도 검증이 남는다.

따라서 기존 편집기 패널의 수명·가리기·보내기 판단·제공자 선택·구독 프로그램의 도구/종료 정책은 그대로 유효하다. 새 내부 IPC를 켜기 전에 문서 읽기/편집·선택·실행 취소 비교와 실행 중 대화 전환의 격리를 통과시켜야 한다. 구현 세부와 보관 이행은 [연결 계약](../../plans/workspace-ui-contracts.md)에 적는다. 공용 패널을 실제로 켜고 형식별 검증을 마친 범위부터 결정 0037의 "초점에 따라 편집기 AI 창 교체"를 이 구조로 대체한다.

2026-11-05 후속 구현으로 기본 창의 탭 표시줄에 공용 패널 호스트를 연결했다. 첫 실행 안내 뒤 연결하고, 패널을 열 때만 공간을 예약한다. 접기·탭 전환은 대화나 실행을 끝내지 않는다. 대상·참고는 HWP/HWPX·DOCX/ODT·Markdown/텍스트 범위다. 긴 글 작성기·HWP 전체 실행 되돌리기와 나머지 형식을 이행하기 전까지 기존 편집기 패널도 유지하므로, 아직 결정 0037의 배선 전체를 대체하지 않는다. 실제 구독과 Windows 설치본은 별도 확인이 남았다.

## 택하지 않은 것

- **문서 탭을 고를 때 대화를 자동으로 바꾸기:** 사용자가 확정한 대화 선택 방식과 맞지 않고, 진행 중 작업·작성 중 요청의 대상이 바뀔 수 있다.
- **기존 편집기 패널을 먼저 없애고 새 패널을 나중에 연결하기:** 문서별 선택·도구·되돌리기·허락 기능이 빠진 상태를 사용자에게 내놓게 된다.
- **현재 활성 탭으로 도구 요청을 보내기:** 모델의 늦은 답이 다른 문서를 바꿀 수 있다. main이 등록한 문서 정체와 실행 바인딩을 사용한다.
- **실시간 참고에 저장본/MCP 출력을 그대로 쓰기:** 저장하지 않은 변경을 놓치거나 가리기 경계를 우회한다. 검증된 현재 자료 읽기 어댑터가 준비되지 않은 형식은 지원하지 않는 이유를 보인다.
- **첫 단계부터 다른 창 접근·대화 간 병렬 편집을 함께 구현하기:** 대상 수명과 같은 문서의 충돌 처리를 더 넓힌다. 단일 창/직렬 실행으로 격리 계약을 먼저 검증한다.

## 결과와 확인

- 문서 포커스, 선택한 대화, 실행 대상을 서로 다른 상태로 다룰 기준을 정했다.
- 실행 바인딩 모델은 가짜 문서 endpoint로 소유자·세대·도구·호출 짝, 참고 쓰기 거절, 대기열·중단·시간 초과·늦은 답을 검사한다. 실제 모델이나 파일 쓰기를 실행하지 않는다.
- 이 기록은 전체 계획 완료·문서 간 편집 지원·설치본 확인·새 버전 공개를 뜻하지 않는다. 자동 검사와 실제 Windows 설치본 사람 확인은 단계별로 상태 문서에 따로 남긴다.
