# 작업 화면 개편 계획 — 문서 분할과 공용 AI 도우미

상태: **단계별 구현 중**(2026-11-05). 화면 나누기 진입점과 키보드 조작, 공용 패널 공간 계산과 실행 바인딩의 기반을 구현했다. HWP·DOCX·Markdown 어댑터와 전용 통신, 실행 바인딩을 잇는 메인 제어기도 연결했다. **공용 패널·대상/참고/대화 선택기와 선택적 셸 배치, 셸 전용 IPC·실제 문서 목록·공유 기록 연결을 구현했다. 기본 화면의 준비 서비스와 구독 전송은 아직 연결하지 않았다.** 화면 분할, 창에 하나인 AI 도우미, 문서 도구와 AI 도구의 분리는 요구사항이다. 추가 논의에서 **AI 패널은 하나이고, 그 안에서 대화를 선택해 작업하는 방식**을 사용자가 정했다. 대화 선택은 문서 탭 선택과 분리한다. 초기 구현 정책과 이행 범위는 [결정 0107](../tracking/decisions/0107-workspace-ai-conversations.md), 조사한 도구·보관 계약은 [연결 계약](workspace-ui-contracts.md)에 적었다.

## 1. 목표와 범위

두 문서를 비교하거나 한 문서를 참고해 다른 문서를 고칠 때, 창을 두 개 띄우고 AI 창도 각각 다루는 부담을 줄인다.

### 사용자가 요청한 것

1. 탭으로 열린 문서를 **한 창에서 좌우 또는 위아래 두 칸으로** 볼 수 있다.
2. **AI 도우미는 오피스 창에 하나만** 있고, 문서 영역 밖의 같은 위치에 머문다.
3. 문서에 관한 도구는 문서 영역에, AI에 관한 도구는 AI 도우미 영역에 둔다.
4. 문서 형식에 맞는 편집 메뉴는 유지하되, AI 도구의 위치와 사용법은 형식마다 같게 한다. 특히 HWP에는 공통 AI 작업 도구 모음을 제공하고, DOCX·Markdown의 문서 리본에 섞인 AI 작업은 공용 AI 패널로 옮긴다.
5. 공용 도우미에서 **“A 화면의 a 자료를 읽어서 B 화면의 b에 적용해 줘”**처럼 참고 문서와 편집 대상이 다른 요청을 처리한다. 한쪽을 읽고 다른 쪽을 고치는 일이 대표 사용 사례다.
6. 공용 AI 패널 안에서 **여러 대화 가운데 하나를 선택해** 작업한다. 대화마다 기록·작성 중인 요청·첨부·참고 문서·수정 대상·프로젝트·작업 상태를 따로 유지한다. 문서 탭을 클릭하는 것만으로 대화를 바꾸거나 기존 대화들을 한 기록으로 합치지 않는다.

### 함께 개선할 것

- 설정 모달, 모델 선택기, 첫 실행 안내의 키보드 조작.
- 연결된 AI와 이번 요청에 사용하는 AI의 구분.
- 빈 문서 만들기와 AI 초안 만들기의 구분, 작은 창에서의 홈 배치.
- 작은 상태 글자의 가독성과 공용 조작의 위치.

함께 개선할 항목은 핵심 화면 구조를 바꾼 뒤 별도 단계로 진행한다. 문서 엔진의 저장·내보내기 동작, 로그인 방식, 제공자 선택·요금 정책의 변경은 이 계획에 포함하지 않는다. 엔진 변경이 필요해지면 해당 모듈 지침에 따라 별도로 판단한다.

## 3. 목표 화면과 조작

### 3.1 기본 배치

기본안은 오른쪽 공용 AI 패널이다. 기존의 왼쪽 배치 설정도 유지한다. 어느 쪽이든 패널은 분할된 문서 한 칸에 속하지 않고 창의 콘텐츠 높이 전체를 쓴다.

```text
┌──────────────── 문서 탭 ─────────────── [화면 나누기 ▾] [AI 도우미] ┐
│ 문서 A의 메뉴·도구 │ 문서 B의 메뉴·도구 │ AI [경력 자료 반영 ▾] [+]│
│                   │                   │ 수정: 문서 B ▾           │
│ 문서 A            │ 문서 B            │ 참고: 문서 A             │
│                   │                   │ 요약 · 다듬기 · …        │
│                   │                   │ 대화와 작업 결과         │
│                   │                   │                          │
│                   │                   │ 입력 · 첨부 · 모델 · 중단│
└───────────────────┴───────────────────┴──────────────────────────┘
```

```text
┌──────────────── 문서 탭 ─────────────── [화면 나누기 ▾] [AI 도우미] ┐
│ 문서 A의 메뉴·도구                     │ AI [경력 자료 반영 ▾] [+]│
│ 문서 A                                │ 수정: 문서 B ▾           │
├───────────────────────────────────────┤                          │
│ 문서 B의 메뉴·도구                     │ 대화와 작업 결과         │
│ 문서 B                                │                          │
│                                       │ 입력 · 첨부 · 모델 · 중단│
└───────────────────────────────────────┴──────────────────────────┘
```

위아래 배치에서도 AI 영역은 둘로 나뉘지 않는다. 문서별 메모·개요·쪽 미리보기처럼 문서에 속하는 보조 패널은 해당 문서 영역에 남는다.

### 3.2 화면 나누기

- 탭 표시줄의 **화면 나누기**에서 `좌우로 보기 / 위아래로 보기 / 나누기 해제`를 고른다. 메뉴는 마우스와 키보드 모두로 연다.
- 열려 있는 두 문서로 시작하고, 다른 문서를 탭 또는 대상 목록에서 골라 한 칸을 바꿀 수 있다. 문서가 하나일 때 같은 문서 사본을 여는 기존 동작은 메뉴에서 그 뜻을 알린 뒤 제공한다.
- 탭 오른쪽 클릭과 가장자리 드래그도 유지한다. 드래그 미리보기는 AI 영역을 제외한 문서 영역을 기준으로 나눌 위치를 보여 준다.
- 구분선 조절·더블클릭으로 반반·분할 해제·재시작 복원은 기존 동작을 재사용한다. 분할 해제는 문서를 닫거나 저장하지 않는다.
- 저장하지 않은 문서, 같은 문서의 두 사본, 복구 뒤 아직 불러오지 않은 탭의 기존 보호를 유지한다. 같은 문서 사본끼리 실시간 동기화하는 일은 추가하지 않는다.

### 3.3 AI 대상 표시

- 패널 머리에 대상 문서의 이름·형식·현재 칸을 표시하고, 해당 문서 칸에도 같은 표식을 보인다. 색만으로 구분하지 않는다.
- 문서 칸의 초점, 선택한 대화, 그 대화의 수정 대상을 구분한다. 문서 칸을 클릭해도 선택한 대화와 이미 지정한 대상은 유지한다. 새 대화를 만들 때 현재 문서를 최초 대상의 제안값으로 쓰고, 이후에는 대상 목록이나 명시한 요청으로 바꾼다.
- 선택한 글을 AI 패널로 넘길 때 문서의 초점이 빠져도 선택 범위가 유지되도록 스냅숏을 받는다. 내용이 바뀌었으면 편집기 쪽에서 다시 검사한다.
- 한 요청의 편집 대상은 한 문서로 시작한다. 다른 열린 문서는 요청문에서 참고 문서로 명시하거나 목록에서 골라 붙인다. 화면에 함께 보인다는 이유로 두 문서 전체를 자동 전송하지 않는다.
- 요청의 대상을 해석하고 필요한 선택을 마친 뒤에는 실행 대상·선택 범위·프로젝트를 고정한다. 다른 문서를 눌러도 진행 중인 작업의 대상이 바뀌지 않는다. 패널은 어느 문서에서 작업 중인지 계속 표시한다.

### 3.4 A를 읽어 B에 적용하는 요청

예: **“왼쪽 경력 자료의 프로젝트 이력을 읽어서 오른쪽 이력서의 경력 표에 반영해 줘.”** 서로 다른 형식의 문서 조합도 각 편집기가 지원하는 읽기·편집 범위에서 처리한다.

1. 요청에서 참고 문서 A와 편집 대상 B, 읽을 범위 a와 고칠 위치 b를 구분한다. 파일 이름, 요청 당시 좌우·위아래 칸, `@문서` 또는 문서 선택 칩으로 지정할 수 있다. 전송 뒤 화면 배치를 바꿔도 A·B가 바뀌지 않게 문서 정체와 연결한다.
2. 대응하는 문서와 범위가 하나로 정해지면 `참고: A의 a / 수정: B의 b`를 패널에 표시한다. 제목이 같은 문서·이름 없는 탭이 여럿이거나 b를 특정할 수 없으면 선택 목록으로 확인하고, 임의의 문서를 고치지 않는다. 요청문이 B를 명시한 경우에는 현재 초점이 A에 있다는 이유로 A를 편집 대상으로 삼지 않는다.
3. A의 실행기에서 **저장하지 않은 변경을 포함한 현재 내용**을 읽는다. 디스크에 마지막으로 저장된 사본으로 조용히 대신하거나, 읽기 위해 A를 자동 저장하지 않는다. 기본은 구조화된 글·표와 명시한 선택 범위이며, 이미지·도형 등 추가 입력이 필요한 자료는 해당 읽기 기능의 지원 여부를 확인한다. 현재 내용을 안전하게 읽을 수 없는 형식·범위라면 그 이유를 알리고 적용을 시작하지 않는다.
4. A는 읽기 전용 참고, B는 편집 대상으로 권한을 구분한다. A의 내용에 적힌 지시 때문에 다른 문서를 수정 대상으로 추가하거나 A를 고치지 않는다. B에 적용할 때는 B의 기존 도구와 선택·변경 검사를 사용한다.
5. A에서 읽은 범위·버전과 B의 편집 위치를 기록한다. B가 바뀌면 적용 전에 다시 검사한다. 참고한 A의 버전이 바뀐 경우에도 재읽기나 사용자 판단 없이 오래된 자료를 최신 내용인 것처럼 적용하지 않는다. 참고 문서가 닫히거나 실행기를 잃은 경우의 처리는 5.2절을 따른다.
6. 결과는 B에 표시하고 B에서 되돌릴 수 있게 한다. A를 읽거나 B를 고쳤다는 이유로 원본 파일을 자동 저장하지 않는다. 결과 안내에는 참고한 문서와 바꾼 문서를 구분해 적는다.

이 요청은 **선택한 대화 안에서 여러 문서를 참고하고 한 문서를 고치는 구조**다. 예를 들어 `경력 자료 반영` 대화는 A와 B를 함께 다루고, `발표 초안` 대화는 다른 문서를 대상으로 따로 이어갈 수 있다. 화면을 실제로 나눴을 때만 쓸 수 있는 기능으로 제한하지 않고, 같은 창의 열린 문서 탭에도 같은 문서 지정 방식을 제공한다.

### 3.5 대화 선택

- 패널 맨 위에 `[대화 제목 ▾]`와 `[새 대화]`를 두고, 대화 목록에서 찾아 고른다. 목록에는 제목·프로젝트·수정 대상·최근 시각·실행 중 또는 확인 대기 상태를 구분해 보인다. 제목이 같은 대화도 구분할 수 있어야 한다.
- 선택하면 해당 대화의 기록·작성 중인 요청·첨부·참고 문서·수정 대상·프로젝트·스크롤 위치를 복원한다. 선택 범위와 문서 버전은 보관하되, 다음 실행 전에 여전히 유효한지 다시 검사한다.
- 다른 대화로 이동해도 기존 대화의 실행과 대기열은 그 대화에 남는다. 선택하지 않은 대화의 진행·완료·실패·허락 대기를 작업 목록에 표시하고, 누르면 그 대화로 돌아간다. 허락 카드와 중단 버튼은 대상 대화·문서를 명시한다.
- 기존 문서별·프로젝트 대화도 출처와 연결을 유지한 채 선택할 수 있게 한다. 다른 프로젝트의 대화를 선택했다고 지침·기억·첨부를 현재 대화에 합치거나 새 권한을 자동 허용하지 않는다.
- 대화를 선택하는 것만으로 모델을 호출하거나 문서를 고치지 않는다. 예전 대화에서 쓴 제공자·모델 기록은 이력이며, 다시 실행할 때는 현재 설정과 기존 제공자 선택·동의 규칙을 따른다.
- 문서 탭을 닫는 것과 대화를 지우는 것은 별개다. 문서가 닫혀도 대화는 남고, 그 문서를 대상으로 다시 실행하려면 열림 상태와 정체를 확인한다.

## 4. 문서 도구와 AI 도구의 경계

| 소유 영역 | 도구                                                      | 배치 원칙                       |
| --------- | --------------------------------------------------------- | ------------------------------- |
| 창        | 탭, 파일 열기, 화면 나누기, 공용 AI 패널 열기·접기        | 창의 탭 표시줄과 창 메뉴        |
| 문서      | 저장·인쇄·내보내기, 글꼴·문단·표·쪽·셀·슬라이드·도형 등   | 해당 문서의 리본·도구 모음·메뉴 |
| 문서      | 메모·변경 내용·선택 상태, AI가 이미 만든 결과의 표시·수정 | 해당 문서 영역                  |
| AI        | 대상 문서, 대화 선택·새 대화·기록                         | 공용 패널 머리                  |
| AI        | 요약·다듬기·번역·AI 서식 정리·생성 등 모델을 부르는 작업  | 공용 패널의 작업 도구 모음      |
| AI        | 모델·생각 깊이·프로젝트·참고 문서·첨부·보내기·중단·대기열 | 공용 패널의 입력과 상태 영역    |

이름이 비슷해도 동작으로 구분한다. 사람이 누르는 글꼴·정렬·서식 지우기는 문서 도구이고, AI에게 서식을 고쳐 달라는 요청은 AI 도구다. AI 없이 하는 문서 형식 점검은 문서 영역에 남고, 그 점검 결과를 AI에게 맡기는 작업은 공용 AI 도구에서 시작한다.

### 형식별 적용

- **DOCX·ODT:** 워드 리본의 AI 요약·다듬기·서식 정리·마인드맵 등은 패널로 옮긴다. ODT에서 지원하지 않는 편집은 기존 거절을 유지한다.
- **Markdown·텍스트:** 리본의 AI 묶음을 옮긴다. 블록 편집과 원문 편집에서 쓸 수 있는 작업 차이를 능력 정보로 전달한다.
- **HWP·HWPX:** 같은 공용 AI 작업 도구 모음을 제공한다. 기존 엔진과 플러그인이 지원하는 요청만 연결한다. 버튼을 맞추기 위해 새 문서 편집 기능을 만들지 않는다.
- **엑셀·슬라이드·PDF·HTML·마인드맵·EPUB·다이어그램:** 같은 기준으로 전수 목록을 만든다. AI 검사·분석·번역·생성의 시작점은 패널로 옮기고, 결과의 문서 표시와 수동 편집은 문서 쪽에 남긴다.
- 문서 메뉴·리본·오른쪽 클릭 메뉴에 남는 모델 호출 시작점이 없는지 확인한다. 단축키는 공용 패널의 해당 작업으로 연결한다.
- 지원하지 않는 작업을 지원하는 것처럼 보이지 않는다. 작업 목록의 순서와 이름은 공통으로 유지하고, 사용할 수 없는 항목은 비활성 상태와 이유를 제공한다. 일시적 조건(선택 없음·읽기 전용·연결 확인 중)도 구분한다.
- 빠른 작업은 기존 동작을 조사해 `입력란에 요청 채우기`와 `확인 뒤 실행`을 구분한다. 자리만 옮긴 버튼이 새로 자동 전송을 시작하지 않게 한다.

## 5. 구현 구조 제안

이 절의 이름과 계약은 **설계 제안**이다. 기존 코드를 확인하며 더 작은 변경으로 같은 요구를 충족할 수 있으면 근거와 함께 조정한다.

### 5.1 셸이 화면 공간을 소유한다

- `AppFrame.tsx` 아래에 공용 AI 패널 영역을 두고, `TabManager.layout()`은 탭 표시줄과 AI 패널 공간을 제외한 문서 사각형만 배치한다. 문서 두 칸과 구분선도 그 사각형 안에서 계산한다.
- 셸 DOM에 AI 패널을 그리는 안을 우선 시험한다. 편집기 `WebContentsView`가 그 영역을 덮지 않도록 한다. 단순히 CSS의 `z-index`를 높이는 방식으로 해결하지 않는다.
- AI 패널 너비·좌우 위치·접힘 상태와 문서 분할 상태를 별도로 관리한다. 문서 탭을 바꿀 때 패널이 새로 생기거나 다른 위치로 이동하지 않는다.
- UI 배율·운영체제 DPI·창 크기 변경 때 메인과 화면이 같은 좌표계를 쓰게 한다. 작은 창에서는 AI 패널을 일시적으로 레일로 접어 두 문서의 최소 공간을 확보할 수 있으며, 사용자가 정한 너비를 덮어쓰지 않는다. 최소 공간조차 안 되는 크기의 처리와 안내는 0단계 시제품에서 확정한다.
- 홈에서도 패널 인스턴스는 하나다. 대상 문서가 없으면 기존 홈 질문의 자료 범위를 명시하고 문서 편집 도구는 내놓지 않는다. 홈 질문과 문서 대화의 저장 방식을 임의로 합치지 않는다.
- 발표·인쇄 미리보기처럼 문서만 보는 화면에서는 패널과 분할 조작을 숨겼다가 원래 상태로 복원한다.

### 5.2 AI 화면과 문서 실행기를 분리한다

현재 `AgentSkill`은 지시문·도구 목록·문맥·실행기를 묶는다. 공용 AI 화면에서 각 편집기의 DOM과 엔진을 직접 가져오는 대신, 편집기에 남겨 둔 실행기에 요청한다.

```text
공용 AI 패널 / AgentLoop
  ├─ 모델 호출 → 기존 ai:* 창구 → selectAiProvider → 제공자
  └─ 문서 도구 요청(runId, 대상, 호출)
        → 셸의 검증·라우팅
        → 대상 편집기의 실행기
        → 기존 skill / 선택 검사 / 변경 표시 / 실행 취소
        → 도구 결과를 원래 요청에 반환
```

- 공용 패널은 `AiComposer`, `AiModelPicker`, 보내기 문지기, 연결·오류·사용량·대기열·프로젝트·사용자 MCP 허락 부품을 재사용한다.
- 편집기별 어댑터는 문서 정체, 읽기 전용 여부, 지원 작업, 선택 범위, 도구 목록·지시문·문맥, 도구 실행과 결과를 제공한다. 기존 `verifyResponse`와 실행 취소 단위도 빠뜨리지 않는다.
- 참고 문서의 어댑터는 화면의 현재 상태를 읽는 진입점과 읽은 범위·버전도 제공한다. 한 실행은 편집 대상 한 개와 명시한 참고 문서들의 읽기 바인딩을 별도로 가진다. 모델이 반환한 도구 요청만으로 읽기 바인딩을 쓰기 대상으로 승격하지 않는다.
- 모델 목록과 도구 목록은 대상 편집기가 실제로 제공할 수 있는 것만 사용한다. 모든 편집기 소스와 도구 스키마를 공용 화면에 한꺼번에 싣지 않는다.
- 메인 경유 요청·응답 패턴은 기존 [열린 문서 연결](../../apps/shell/src/main/mcp/open-documents-bridge.ts), [워드 연결](../../apps/shell/src/main/mcp/docs-bridge.ts), [다이어그램 연결](../../apps/shell/src/main/mcp/diagram-bridge.ts)을 참고한다. 기존 공개 MCP 출력을 새 내부 계약으로 사용하거나 그대로 바꾸지 않는다.
- 새 내부 IPC는 가칭 `workspace-ai:*`처럼 별도 이름을 쓴다. 기존 `ai:*`와 구독 IPC를 중복 등록하지 않는다. 요청은 허용된 창·문서 보기·도구와 짝이 맞는 응답만 받는다. 임의 JavaScript 실행이나 임의 채널 호출을 내주는 범용 창구는 만들지 않는다.
- 각 대화의 실행은 하나의 바인딩을 가진다. 최소한 `conversationId`, `runId`, 실행 당시 대상 탭과 문서 정체, 편집기 세대, 선택 스냅숏, 프로젝트 정체를 묶는다. 경로 문자열이나 현재 활성 탭·선택한 대화만으로 진행 중 실행의 대상을 다시 찾지 않는다.
- 취소·닫기·새로고침·응답 시간 초과는 바인딩을 무효화한다. 늦은 응답은 새로 열린 같은 탭이나 다른 문서에 적용하지 않는다. 편집 요청은 시간 초과 뒤 자동 재전송하지 않는다.
- 문서가 닫히거나 새로 불러와 실행기를 잃으면 해당 작업을 멈추고 알린다. 문서를 바꿔 계속하거나, 저장된 파일에 조용히 대신 적용하지 않는다.
- 참고 자료 읽기·가리기·저장하지 않은 변경 확인은 기존 보호를 그대로 통과시킨다. 공개 MCP 읽기를 재사용해 가리기 경로를 우회하지 않는다.

### 5.3 대화와 실행의 수명

- 대화는 안정적인 식별자로 관리하고, 패널·문서 보기·실행과 수명을 분리한다. 기존 문서별 대화, 프로젝트 대화, 홈의 임시 대화는 임의로 합치거나 지우지 않는다. 저장 위치와 이전 기록 연결은 기존 보관 계약을 확인해 0단계에서 설계한다. 문서가 여러 개인 대화를 새로 특정 파일 하나의 경로 해시에만 묶지 않는다.
- 실행 중 문서 초점이나 선택한 대화를 바꿔도 기존 실행은 원래 대화·문서에 묶인다. 응답·변경 기록·실패·허락 요청은 원래 대화에만 쌓인다. 대화별 대기열의 각 요청도 넣을 때의 대상과 선택 범위를 보존한다.
- 한 대화 안의 실행과 대기열은 순서를 지킨다. 다른 대화의 새 작업을 병렬로 시작할지 공용 대기열에서 기다리게 할지는 11절의 별도 결정이다. 공용 패널이라는 이유만으로 모든 대화를 하나의 실행 상태나 중단 신호로 묶지 않는다.
- 패널을 접는 것은 중단과 구분한다. 접어도 창의 작업 표시에서 대상과 진행·중단 버튼에 접근할 수 있어야 한다. 앱 종료·화면 새로고침은 기존 취소·하위 프로세스 종료 정책을 따른다.
- 문서 변경 표시와 실행 취소는 문서 실행기가 맡는다. AI 도구가 반환하는 변경 기록에는 대상 정체를 붙여, 다른 문서의 되돌리기를 누르는 일을 막는다.
- 구독 프로그램에 새 도구를 켜지 않는다. AI 화면의 이동은 기존 앱 도구 실행 경계를 유지한다.

## 6. 공통 UX 보완

1. **모달:** 설정·연결·확인 창은 열릴 때 초점을 안으로 옮기고, Tab·Shift+Tab을 활성 컨트롤 사이에서 순환시키며, 닫으면 호출한 조작으로 돌아간다. 배경 조작도 막는다.
2. **첫 실행 안내:** input·textarea·select·편집 가능한 영역에서는 Enter·좌우 화살표를 단계 이동으로 받지 않는다. 한글 조합 중 Enter도 가로채지 않는다. 초점 순환은 버튼 외 입력·링크도 포함한다.
3. **모델 선택기:** 열면 현재 선택에 초점을 두고 ↑↓·Home·End로 탐색하며 Enter로 선택한다. Escape는 변경 없이 닫고 호출 버튼으로 복귀한다. 긴 이름 전체를 확인할 수 있게 한다.
4. **AI 상태:** `현재 사용: 제공자 · 모델`을 먼저 표시하고 연결 가능한 다른 제공자는 별도 상태로 보여 준다. 실제 선택은 기존 `selectAiProvider` 결과를 쓴다. 자동·무료·종량 허용·로컬 서버의 기존 선택 규칙은 바꾸지 않는다.
5. **홈:** 일반 생성 카드는 `새 워드 문서`처럼 행동을 드러낸다. AI 초안 만들기는 별도 행동으로 구분한다. 작은 창에서는 자주 쓰는 종류와 더 보기를 우선 배치하고, 기존 종류 숨김·순서 설정은 보존한다. 문서 종류 전체 목록은 계속 접근할 수 있다.
6. **가독성:** 모델·대상·진행 상태를 10~12px의 보조 글자와 같은 무게로 두지 않는다. 작은 본문 글자의 대비 목표는 4.5:1로 잡고, 조작 영역과 UI 배율을 함께 점검한다. 문서 내용의 글꼴·색·조판은 바꾸지 않는다.
7. **처음 보이는 안내:** 설치본 관찰에서는 업데이트 창과 AI 설정이 함께 떠 있었다. 현재 빌드에서 발생 조건을 먼저 재현하고, 처음 실행 안내·연결 안내·업데이트 중 동시에 조작해야 하는 모달이 하나를 넘지 않도록 순서를 정한다. 관찰 한 번만으로 항상 발생하는 결함으로 적지 않는다.

공간 시제품은 합성 문서 `WebContentsView`와 로컬 가짜 응답만 사용한다. 실제 구분선 컴포넌트를 확대된 화면 틀 안에서 마운트하고, 포털로 그린 구분선이 네이티브 문서 경계와 맞는지 검사한다. 작은 창에서는 열린 패널이 일시적으로 레일로 접히고, 레일까지 둘 수 없으면 문서 공간을 우선한다. 저장한 패널 너비와 분할 비율은 덮어쓰지 않으며 화면에서만 최소 칸 크기에 맞춘다. 기존 앱에서는 검증된 공용 호스트가 붙기 전까지 이 패널 공간을 예약하지 않는다.

아래 체크리스트는 전체 개편의 완료 기준이다. 기반 모델·시제품 검사만으로 실제 문서 편집이나 설치본 확인을 완료 처리하지 않는다.

- [ ] **A1 분할 발견:** 문서 탭에서 탭 표시줄의 화면 나누기 버튼을 한 번 열어 좌우·위아래·해제에 접근한다. 홈·도움말·발표 탭에서는 적용 불가 이유가 분명하다.
- [ ] **A2 문서 보존:** 서로 다른 두 문서와 같은 문서 사본을 배치하고, 칸 교체·비율 조절·해제·재시작 복원 뒤에도 문서 내용과 저장 상태가 유지된다.
- [ ] **A3 패널 한 개:** 한 문서·좌우·위아래 세 배치에서 공용 AI 패널은 하나이며, 문서 칸에 별도 AI 패널이나 중복 레일이 남지 않는다. 기본 창과 떼어 낸 창은 11절에서 정한 범위대로 각각 검사한다.
- [ ] **A4 대상 고정:** A에 보낸 작업 중 B를 클릭해도 B에 적용되는 도구 호출은 0건이다. A를 닫거나 다시 불러오면 늦은 결과를 다른 문서에 적용하지 않는다.
- [ ] **A5 선택 보존:** 문서의 선택 부분을 대상으로 입력란에 초점을 옮겨 요청해도 원래 범위만 사용한다. 그 범위의 내용이 바뀌었으면 기존 편집기 검사가 거절한다.
- [ ] **A6 기존 편집 보존:** 같은 합성 문서·같은 도구 입력으로 기존 실행기와 공용 패널의 결과를 비교한다. 변경 표시·실행 취소 단위·읽기 전용 거절·저장 결과가 같고, 지원하지 않는 도구는 실행되지 않는다.
- [ ] **A7 도구 소유:** 4절의 전수 목록에 따라 문서 리본·메뉴에 모델 호출 작업이 남지 않고, HWP·DOCX·Markdown에서 공용 AI 작업에 같은 위치로 접근한다. 모델을 부르지 않는 문서 기능은 원래 위치에서 쓸 수 있다.
- [ ] **A8 전송 정책:** 문서 열기·칸 클릭·분할·패널 열기·모델 목록 탐색만으로 모델 요청이 나가지 않는다. 두 문서 표시만으로 참고 문서가 첨부되지 않는다. 보내기·허락·요금 판단은 기존 가짜 연결 시험을 통과한다.
- [ ] **A9 대화 보존:** 공용 패널에서 여러 대화를 찾아 선택하고 새 대화를 만든다. 문서 탭을 클릭해도 선택한 대화와 지정한 대상이 바뀌지 않는다. 기존 문서별·프로젝트 대화가 없어지거나 자동으로 섞이지 않고, 제목 없는 문서·다른 이름 저장·프로젝트 전환·문서 닫기 뒤에도 기록의 연결을 확인한다.
- [ ] **A10 키보드:** 설정의 Tab 순환·닫기 복귀, 입력칸의 좌우 화살표·Enter·한글 조합, 모델 목록의 ↑↓·Home·End·Enter·Escape를 모두 검사한다. 배경 문서에 초점이나 입력이 새지 않는다.
- [ ] **A11 현재 상태:** 홈과 AI 패널의 현재 제공자·모델이 실제 실행에 선택되는 값과 일치한다. 추가 연결된 제공자와 작업 대상·참고 문서는 구분되어 보인다.
- [ ] **A12 화면 조건:** 1600×900·1280×720·1024×768, UI 배율 100%·125%·150%, 밝게·어둡게·시스템 모드에서 필수 조작이 가려지지 않는다. 공간이 부족한 경우의 접힘·최소 크기 규칙도 설명된 대로 동작한다.
- [ ] **A13 언어:** 새 화면 문구와 도움말이 21개 언어에 있고, 긴 번역과 아랍어·히브리어 방향에서도 대상·보내기·중단을 구분할 수 있다.
- [ ] **A14 복구와 종료:** 진행 중 새로고침·렌더러 종료·앱 종료·중단에서 요청과 하위 프로세스가 기존 정책대로 끝난다. 복구 사본·세션 기록·실행 중이 아닌 대화는 유지된다.
- [ ] **A15 문서 간 적용:** A에만 저장하지 않은 표식 자료를 넣고 “A의 a를 읽어 B의 b에 적용”을 요청한다. 그 최신 자료가 B의 지정 위치에 반영되고 A의 내용과 디스크 파일은 바뀌지 않는다. 요청 때 초점이 A에 있어도 B만 고친다. 같은 제목·범위 모호·자료 읽기 불가·읽은 뒤 A 또는 B 변경·중간 탭 재배치·취소도 검사하며, 두 방향 분할과 분할하지 않은 탭 상태 모두에서 같은 문서 정체를 사용한다.

### 공용 패널과 선택기를 이어서 구현한 결과 (2026-11-04, macOS)

- `WorkspacePanel`과 `WorkspacePanelController`를 기존 대화 컨트롤러·실행 호스트에 연결했다. 대화의 출처·프로젝트·대상·최근 시각·실행/허락 상태를 표시하고, 대상 목록은 같은 제목의 사본도 순번·형식·칸으로 구분한다. 기존 대화 열기는 대상을 자동 지정하지 않고, 새 대화에서만 클릭 당시의 초점 문서를 최초 대상으로 제안한다. 불러오지 않은 복구 탭·지원하지 않는 문서는 목록에서 비활성이다.
- 참고는 문서와 `문서 전체 / 선택한 부분`을 고른 뒤 **참고 추가**를 눌러야 취득한다. 패널에는 불투명한 참고 식별자와 바인딩만 두고 본문은 넘기지 않는다. 대화·탭 선택만으로 참고 읽기·모델 호출·파일 저장은 하지 않는다. 늦은 이력/대상/참고 답은 원래 대화에만 반영하고, 오래된 대상 답이나 닫힌 문서는 거절한다. 대상 변경이 실패하면 이전 대상을 전송 가능한 상태로 남기지 않는다.
- `AppFrame.workspace`는 실제 호스트를 주입하는 선택적 입구다. `TabManager.setWorkspacePanel()`이 반환하는 예약 영역을 패널·홈·분할 구분선에 함께 전달한다. 패널은 확대된 틀 밖의 포털에 두고 안쪽 조작만 UI 배율을 적용한다. 레일·접기·발표 중 숨기기와 복귀가 문서 분할 비율이나 대화 실행을 바꾸지 않는다. 탭 표시줄의 공용 AI 열기/접기도 이 호스트가 있을 때만 나타난다. 일반 시작 경로는 호스트를 주입하지 않으며 기존 편집기 AI 창을 유지한다.
- 기존 `AiComposer`·허락/되돌리기 카드를 재사용했다. 문서 바인딩이 없거나 읽기/선택 중·닫힘 상태면 입력은 유지하고 전송과 대기열 추가만 막는다. 접힌 레일에서도 원래 대화의 작업을 선택하거나 중단할 수 있다. 화면에 복사해 전달한 실행 식별자로 중단이 되지 않던 오류를 찾아, 컨트롤러·대화·실행·세대 네 값을 모두 비교하도록 고쳤다. 다른 소유자/세대의 중단은 계속 거절한다. 새 문구는 21개 언어다.
- 단위/DOM 검사는 실제 실행 호스트와 가짜 전송을 사용해 대화별 초안·참고·스크롤 복원, 늦은 답, 연결 차단 뒤 초안 유지, 중복 전송 차단, 닫힌 대상, 패널 접기 뒤 중단을 확인했다. 네이티브 화면 시험 `e2e/workspace-panel.spec.ts`는 실제 패널과 합성 `WebContentsView`로 100/125/150% 배율·좌우 패널·단일/좌우/위아래·밝고 어두운 테마 36개 조합, 좁은 창의 레일, 아랍어 RTL을 확인했다. 조작·초안·참고 범위 선택과 문서 보기의 영역도 확인했다. 모델 호출은 0건이다. 이 시험은 실제 문서 엔진을 패널에서 부르는 통합 검사가 아니다.
- **검사 결과:** 셸 빌드, 셸/UI 형 검사, 변경 코드 lint, 라이선스·테마 색·영어 주석·도움말·스킬 버전·원본 표기 검사가 통과했다. 관련 셸 검사 202건과 UI 전체 1,223건 및 추가 전송 차단 회귀 검사가 통과했다. 전체 셸 검사는 3,602건 중 3,597건 통과·2건 건너뜀·3건 실패이며, 실패 3건은 변경 전 HEAD `6717d514`의 임시 사본에서도 같은 두 파일의 28건 통과·3건 실패로 재현됐다. 기존 Mac 단축키/사용자 MCP 환경 전제이며 `findings.md`의 기존 항목과 같다. 전체 서식 검사는 작업 전부터 있던 `.omx/` 상태 JSON 5개만 실패했다. 이 파일은 수정하지 않았다.
- **다음:** 원래 홈/저장 전 문서 기록 연결 위에 프로젝트 믿음·첨부·스킬·MCP·보내기 문지기·구독 전송·사용량을 연결한다. `WorkspacePanelMount`의 선택적 배치나 합성 화면 시험은 이 서비스 배선의 완료를 뜻하지 않는다. 실제 참고 전송의 보안/개인정보 안내, 편집기 중복 패널 이행, HWP 전체 실행 되돌리기와 나머지 형식도 남았다.

### 실제 셸 서비스 연결 확인 (2026-11-05, macOS)

- `workspace-ai:panel-*` 전용 IPC와 preload, 실제 문서/기록 출처 목록, 공유 로컬/프로젝트 기록 서비스와 화면 실행 호스트를 연결했다. 목록은 문서 본문·선택을 읽거나 복구 탭을 열지 않는다. 연결/프레임/패널 세대와 요청 크기를 검사하고 원문 오류는 실패 응답에 넣지 않는다.
- 복사된 IPC를 사용하는 단위 통합 검사에서 출처 밖/다른 프레임/이전 세대/잘못된 요청 거절, 참고 본문을 선택기에 노출하지 않는 것, 공유 버퍼·기존 기록·프로젝트 가시성/쓰기 거절, 준비 응답보다 빠른 중단, 늦은 응답과 영역 갱신/해제를 확인했다. 실제 준비 서비스가 연결되기 전까지 프로젝트 실행 바인딩은 `null`만 받는다.
- `e2e/workspace-panel-services.spec.ts` 1건 통과. 빌드한 셸의 실제 preload·패널 선택기·작성기·되돌리기 카드와 DOCX/Markdown 편집기를 연결했다. 저장 전 참고로 대상만 고치기, 다른 대화의 기록 보존, 전체 실행 되돌리기, 참고 변경 때 가짜 전송 중단, 늦은 도구 무시, 두 원본 파일의 바이트 보존과 저장한 대화의 재읽기를 확인했다. 실제 모델 호출은 0건이다.
- 최종 검사: 셸 전체 3,607건 통과·2건 건너뜀, 기존 macOS 실패 3건은 이전과 같다(탭 단축키 1건, 사용자 MCP 2건). 기록 저장소 전체 135건 통과·2건 건너뜀. 셸/워드 형 검사, 변경 파일 ESLint·Prettier, 셸 빌드, 라이선스·화면 색·영어 주석·도움말 언어·스킬 버전·원본 제작사 표기·`git diff --check` 통과. 전체 서식 검사는 기존 미추적 `.omx/`의 JSON 5개만 실패한다([기록](../tracking/findings.md)).
- 프로젝트 믿음·첨부·스킬·MCP·보내기 문지기·구독 전송·사용량은 아직 호스트의 주입 자리다. 홈 임시/저장 전 문서 기록의 원래 호스트와 기존 기록의 실시간 갱신/이동 전달도 남았다. 일반 시작 경로는 패널 호스트를 켜지 않으며, 기존 편집기 AI 입구는 유지한다.

### 원래 대화 호스트를 이어서 연결 (2026-11-05, macOS)

- 홈 임시 대화는 전용 `workspace-ai:memory-*` 통신으로 원래 `KbAskPanel`에서 읽고 쓴다. 따로 파일로 옮기지 않으며, 열어 둔 동안 기존 홈 전송을 잠근다. 원래 화면·모델 이력과 프로젝트 화면 뒤에 보관한 홈 대화를 구분한다. 연결/프레임/요청 세대와 크기를 검사하고, 해제·새로고침·종료·시간 초과 뒤의 답은 폐기한다.
- 저장 전 문서는 원래 호스트가 정한 참조로 목록에 나타나며 첫 메시지 버퍼도 같은 저장소에서 읽는다. 첫 저장의 참조 변경은 대화 id·실행기·초안·참고·스크롤을 바꾸지 않는다. 별도로 열린 두 대화는 합치지 않는다. 다음 요청의 대상이 달라도 이전 답의 출처는 실제 시작한 작업의 대상을 따른다. 기존 기록에 새 메시지가 생기면 그 대화만 갱신하며 실행 중이거나 늦은 읽기 답이 현재 이력을 덮지 않게 한다.
- 관련 검사 6개 파일 57건 통과. 셸 전체는 3,617건 통과·2건 건너뜀·기존 Mac 환경 실패 3건(탭 단축키 1건, 사용자 MCP 2건)이며 기존 기록과 같다. 셸/워드 형 검사와 변경 코드 lint가 통과했다.
- 빌드한 앱의 `e2e/workspace-panel-services.spec.ts` 1건 통과. 기존 문서 편집/중단/되돌리기 외에 원래 문서 호스트의 저장 전 버퍼·첫 저장 IPC 결과·원래 참조로 이어 쓰기와, 실제 홈 화면에 기록 추가가 반영되는 것을 확인했다. 파일 저장 창을 누른 시험이나 Windows 설치본 확인은 아니다. 실제 모델 호출은 0건이다.
- 기본 화면의 준비 서비스·구독 전송·사용량, 편집기 중복 패널 이행과 나머지 문서 형식은 남았다. 실제 구독 호출은 쓰지 않는다.

### 단위·계약·화면 시험

- 기존 `apps/shell/tests/split-layout.test.ts`, `split-state.test.ts`, `split-renderer.test.ts`, `split-memory.test.ts`, `split-wiring.test.ts`에 AI 영역을 제외한 좌표와 새 진입점을 연결한다.
- 기존 `packages/ui/tests/split-pane-role.test.ts`의 역할 규칙은 새 구조로 이행한 범위와 독립 편집기에서 필요한 범위를 나눠 점검한다. 사라진 화면 배선을 유지하려고 테스트만 남기지 않는다.
- 내부 문서 연결은 잘못된 창·대상·도구·실행 식별자, 실행기 교체, 시간 초과 뒤 늦은 응답, 중복 편집 거절을 시험한다. 실제 엔진을 통과하는 합성 문서 시험으로 변경·저장·되돌리기를 확인한다.
- `e2e/split-view.spec.ts`를 확장해 `HWP + DOCX`, `HWP + Markdown`, `DOCX + PDF`, `엑셀 + 슬라이드`와 같은 문서 두 사본을 검사한다. HTML·마인드맵·EPUB·다이어그램도 대상 전환과 공용 작업을 한 번씩 덮는다.
- 문서 간 적용은 `DOCX 자료 → HWP 표`, `Markdown 자료 → DOCX 문단`, `엑셀 범위 → 슬라이드 글상자`로 검사한다. 가짜 모델이 A를 읽고 B를 고치는 도구 요청을 내게 하고, A의 저장 전 표식·B의 편집 결과·파일 미저장·되돌리기를 확인한다. 읽기 전용 참고 A에 대한 쓰기 요청과 요청에 없는 문서 C에 대한 접근은 거절되는지 확인한다.
- `e2e/helpers.ts`의 `stubAiReady(app)`와 가짜 제공자를 사용한다. 모델 응답을 지연시킨 상태에서 대상 바꾸기·닫기·새로고침·중단을 재현한다. 테스트가 실제 구독 프로그램에 닿지 않는지 먼저 확인한다.
- 대화 P·Q에 서로 다른 초안·첨부·참고 문서·프로젝트를 두고 여러 번 전환한다. P의 응답·사용자 MCP 허락·대기열을 지연시킨 동안 Q를 선택하고, 기록·허락·중단·도구 실행이 원래 대화로만 전달되는지 검사한다. 기존 문서별·프로젝트 기록도 새 대화 선택기에서 열어 보고 자동 병합이 없는지 확인한다.
- 마우스 없이 홈 → 문서 열기 → 분할 → 대상 선택 → 가짜 AI 요청 → 중단 → 설정 → 모델 선택까지 수행한다.
- 작업 전후 문서 내용과 저장·내보내기를 비교한다. 화면 배율·테마 변경이 문서 조판과 결과 파일에 영향을 주지 않는지도 확인한다.

### 빌드와 합치기 전 검사

의존성은 잠금 파일 기준 `npm ci`로 준비하고 Rust 처리 프로그램 등 필요한 빌드 조건을 갖춘다. 뒷단과 preload 변경 뒤에는 `npm run build:all`로 셸과 편집기를 함께 만들고, 빌드한 앱과 설치본에서 확인한다.

```sh
npm run typecheck
npm run lint
npm run format:check
npm test
npm run licenses
npm run check:theme-colors
npm run check:english-comments
npm run check:help-langs
npm run check:skill-version
npm run check:no-genspark
```

변경된 화면의 e2e와 문서 왕복 시험도 함께 통과해야 한다. Windows의 기존 실패는 손대지 않은 기준 사본에서 같은 시험으로 비교하고, 새 실패를 기존 실패로 묶지 않는다.

Windows 설치본에서 먼저 사람 확인을 하고, Mac·Linux는 확인 가능한 환경과 사용자 보고의 범위를 분리해 적는다. 실제 구독 확인은 `docs/operations.md`의 절차와 사용자의 한도 사용 지침을 따르며, 자동 반복 시험으로 쓰지 않는다. 위 목록은 **앞으로 구현 때 수행할 검사**이고, 이 계획 작성 중 통과했다고 주장하는 결과가 아니다.

| 기존 패널 위치·너비·기록 설정을 잃음                           | 저장 형식은 필요한 만큼만 늘리고 예전 값의 읽기·복귀 시험을 둔다. 문서 안 식별자는 바꾸지 않는다                                 |
| 원본 변경을 받아오기 어려워짐                                  | 셸 배치·공용 UI·얇은 편집기 연결을 중심으로 바꾸고 문서 엔진과 벤더 본체는 그대로 쓴다                                           |

## 11. 정한 것과 구현 전에 정할 것

계획을 쓰는 동안 추가 답을 요구하지 않는다. 사용자가 정한 대화 방식과 아직 정하지 않은 실행 정책을 구분한다.

1. **대화 방식 — 사용자 확정(2026-11-04).** AI 패널은 하나이며 그 안에서 작업할 대화를 선택한다. 각 대화는 하나 이상의 문서를 참고하고 지정한 문서를 수정할 수 있다. 대화 선택과 문서 탭 선택은 분리하고, 기존 기록은 자동 병합하지 않는다. 이 항목은 더 이상 양자택일의 미결정 사항으로 두지 않는다. 구체적인 보관·이전 계약은 0단계에서 작성한다.
2. **대상 문서 범위 — 초기 구현 기본안.** 같은 창의 문서만 수정·참고 대상으로 제공한다(결정 0107). 다른 창 접근은 열지 않는다. 떼어 낸 창과 독립 편집기는 공용 호스트가 검증되기 전까지 기존 동작을 유지한다. 이는 개발을 위한 기본안이며 사용자가 따로 고른 정책으로 기록하지 않는다.
3. **기본 위치와 공간 부족 처리 — 공간 모델·시제품 구현.** 새 공용 패널은 오른쪽 기본안이며 기존 좌우 설정을 우선한다. 작은 창에서는 저장한 너비를 보존하고 일시적으로 레일로 접는다. 레일까지 둘 수 없으면 문서에 공간을 주고 창의 진입점으로 접근한다. 기존 설정을 새 저장소로 옮기는 배선과 그 진입점은 실제 호스트 구현 때 검사한다.
4. **빠른 AI 작업의 실행 방식 — 4단계 전수 목록에서 확인.** 요청 채우기·확인 창·즉시 전송의 기존 동작을 기록하고, 사용자 행동 없이 호출이 늘어나는 변경은 하지 않는다.
5. **서로 다른 대화의 동시 실행 — 초기 구현 기본안.** 창마다 AI 실행 하나와 FIFO 대기열을 사용한다(결정 0107). 대기 중에도 다른 대화를 읽거나 초안을 쓸 수 있다. 각 요청은 넣을 때의 대상·선택·프로젝트를 유지하고, 앞선 실행이나 수동 편집으로 문서가 바뀌면 다시 검토하게 한다. 모델을 부르는 호스트와 대화 화면에는 아직 연결하지 않았다.

초기 정책은 결정 0107과 연결 계약에 기록했고, 현재 구현 범위의 구조·내부 계약·셸·UI 지침과 21개 언어의 탭 도움말을 맞췄다. 실제 공용 패널을 켤 때는 동작 규칙·보안/전송 범위·각 편집기 지침과 AI 도움말도 함께 갱신한다. 상태 문서에는 `설계 / 구현 / 자동 검사 / 설치본 사람 확인`을 구분해 남긴다. 이번 기반 구현은 전체 개편 완료나 새 버전 배포를 뜻하지 않는다.
