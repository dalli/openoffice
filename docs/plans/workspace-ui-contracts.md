# 작업 화면 개편: 연결 계약과 이행 순서

상태: **0단계와 실행 바인딩 모델, 2단계의 HWP·DOCX·Markdown 어댑터·전용 통신·메인 실행 제어기 구현**(2026-11-04). [전체 계획](workspace-ui.md)의 대화 선택 요구를 기준으로 현재 코드와 이행 경계를 정리했다. 이 문서의 제안은 공용 AI 패널이나 문서 간 편집이 이미 동작한다는 뜻이 아니다. 아래 실행 바인딩 모델과 편집기 실행 통신은 메인 제어기로 연결했다. 대화별 상태 컨트롤러와 출처별 기록 연결, 새 로컬 대화의 보관도 구현했다. 공용 실행 호스트와 허락·되돌리기 카드 부품도 구현했다. 공용 패널·선택기 부품과 선택적 셸 배치는 구현했지만, 기본 화면의 실제 서비스 호스트/IPC와 구독 전송 배선은 아직 없으며, 기존 편집기 AI 창과 대화 보관 방식은 바꾸지 않았다.

## 이번 구현에서 쓰는 기본안

- 대상과 참고 문서는 **같은 창**의 열린 문서로 한정한다. 경로·제목·좌우 위치는 사람이 고르는 표시이고, 실행 정체는 창·탭·문서 인스턴스·편집기 세대다. 같은 파일의 두 사본은 서로 다른 인스턴스다. 떼어 낸 창과 독립 편집기는 기존 AI 창을 유지하고 다음 이행 단계에서 자기 도우미를 붙인다. 다른 창에 접근하는 길은 만들지 않는다.
- **창마다 실행 하나**를 우선 지원한다. 다른 대화는 열어 읽고 초안을 쓸 수 있으며, 사람이 보낸 요청은 실행 당시의 대상·선택·참고·프로젝트를 담아 FIFO로 기다린다. 대기 중 문서가 바뀌면 그 요청을 멈추고 다시 검토하게 한다. 이전 요청이 같은 문서를 고친 경우도 해당한다. 대화 선택만으로 실행·중단·권한 승인·자동 재전송을 하지 않는다.
- 패널 공간과 문서 분할은 별도 상태다. 기존 좌우·너비 설정을 덮어쓰지 않고 좁은 창에서만 잠깐 접는다. 실제 문서 뷰 위에 DOM을 겹치는 대신 메인의 문서 사각형을 줄인다. 현재는 공간 계산과 가짜 화면 시제품의 검증 단계이며 기본 화면에 빈 AI 패널을 켜지 않는다.
- 기본안의 범위·직렬 실행 정책을 바꿀 때는 새 결정 기록을 남긴다. 결정 0037의 역사와 기존 독립 편집기 동작을 지우지 않는다. 공용 패널이 완성되기 전에 편집기 안 AI 진입점을 없애지 않는다.

## 현재 연결 구조와 넘겨야 하는 것

## 대화 보관과 이전 계약

현재 대화는 한 저장소에 있지 않다.

1. **기존 문서별 기록:** [`ProjectStore`](../../packages/project-store/src/store.ts)의 `resolveChatForFile`, `chatIdByPath`, `rebindChat`와 편집기 `window.projectApi`를 쓴다. 처음에는 경로 해시를 쓰지만 한 번 등록한 chat id는 이름 변경/이동을 따라 안정적으로 유지한다. 제목 없는 기록은 `unsaved-*`이고 첫 저장에서 기존 rebind 경로를 지난다. 새 화면이 새 경로 해시로 기록을 다시 만들지 않는다.
2. **프로젝트 대화:** [`ProjectChatStore`](../../apps/shell/src/main/projects/chat-store.ts)가 `.ieumoffice/chats/<id>.json`과 `<id>.jsonl`을 다룬다. 프로젝트 믿음·외부 PC 기록·쓰기 확인·원자적 정보 저장·동일 대화 직렬 쓰기를 지킨다. [`useProjectChat`](../../packages/ui/src/use-project-chat.ts)의 기존 문서 기록과 프로젝트 기록 구분을 유지한다.
3. **홈 질문:** [`KbAskPanel`](../../apps/shell/src/renderer/src/KbAskPanel.tsx)은 프로젝트를 고르지 않았으면 메모리에만 있고, 프로젝트를 고르면 해당 프로젝트 대화에 보관한다. 별표 그룹으로 좁힌 읽기 범위도 별도다.

공용 선택기는 위 기록을 **출처 참조**로 열어야 한다. `WorkspaceConversationOrigin`이 `legacy-document / project / window-memory / workspace`를 구분한다. 기존 JSONL을 복사·합치거나 문서 닫기 때문에 지우지 않는다. 가져온 대화의 제공자/모델은 기록일 뿐 현재 설정을 바꾸는 명령이 아니다. 기존 MCP의 "이 대화에서 항상 허용"과 서버 끄기 상태도 다른 대화에 옮기지 않는다.

새 다중 문서 대화는 파일 한 개의 경로로 id를 만들지 않고 별도의 무작위 id를 쓴다. 프로젝트를 고른 대화는 기존 프로젝트 파일 형식과 쓰기 함수를 사용한다. `ProjectStore`에 프로젝트 없는 새 대화의 분기를 추가했다. `<userData>/projects/.workspace/v1/<id>.json`은 버전·무작위 id·제목·생성 시각, 같은 이름의 `.jsonl`은 기존과 같은 메시지 형식이다. 기존 JSONL 쓰기·읽기 코드와 크기 제한·첫 답 전 버퍼를 공유하고 문서 경로 맵이나 프로젝트 목록에는 등록하지 않는다. 모르는 정보 버전은 덮어쓰지 않고 거절한다. 이 분기는 아직 앱 화면에서 호출하지 않으며 자동 이전도 없다. 사용자 폴더, 세션 기록, 복구 사본 또는 설정 파일에 대화 본문을 끼워 넣지 않는다.

선택한 대화마다 다음 상태를 따로 소유해야 한다: 이력과 AgentLoop, 작성 중 글·첨부·스킬 칩, 명시한 참고·수정 대상, 프로젝트, 스크롤, 실행·대기열, 허락 카드와 중단 신호. 탭 선택은 이 객체를 교체하는 이벤트가 아니다. 새 대화에서만 현재 문서를 최초 대상의 제안으로 쓴다. 기존 `useProjectChat.openChat`은 화면 전체의 메시지를 교체하는 경로이므로, 한 패널 인스턴스를 재사용하며 실행 중인 대화의 상태까지 바꾸는 식으로 곧바로 연결하면 안 된다.

## 구현된 실행 바인딩 모델

[`workspace-ai-api.ts`](../../apps/shell/src/shared/workspace-ai-api.ts)와 [`run-registry.ts`](../../apps/shell/src/main/workspace-ai/run-registry.ts)는 Electron 없이 검사할 수 있는 **미등록 내부 모델**이다.

- 소유자는 창 id·패널 webContents id·패널 세대다. 편집기 endpoint는 main이 알려진 live view에서 등록한다. 패널이 보내는 경로나 webContents 번호로 endpoint를 만들어 주지 않는다.
- 요청은 `conversationId`, `runId`, 대상의 문서 정체·세대·버전·선택 스냅숏, 명시적으로 취득한 참고 snapshot id·버전, 준비한 프로젝트 정체/문맥 버전을 복사해 보관한다. main은 별도의 단조 증가 `bindingId`를 발급한다. enqueue 이후 작성기 값을 바꿔도 바인딩은 바뀌지 않는다.
- 실행은 창마다 하나이며 대기열은 FIFO다. 실행 모델의 `startNext`는 모델을 호출하지 않는다. 호스트가 실행 직전 기존 `useAiSendGate`/제공자 선택과 준비 결과를 확인한 다음 시작해야 한다. 대기열 수용도 그 판단을 우회하지 않는다.
- 도구 ticket은 허용한 문서 도구 이름·읽기/쓰기·정체·세대·버전·선택만 담는다. 임의 채널 호출이나 JavaScript 실행은 없다. 참고 endpoint에 쓰기 도구가 등록돼 있어도 참고 바인딩으로는 쓸 수 없다. 요청에 없는 C 문서에 접근할 수 없다.
- 한 실행에서 도구 호출 하나만 진행하고 call id를 한 번만 소비한다. 답은 실제 IPC sender와 원래 패널 세대·대화·실행·binding id·호출·도구·문서 세대가 모두 맞아야 받아들인다. 읽기 답이 문서를 바꾸거나 버전을 바꾸면 실패한다. 검증된 대상 쓰기만 자기 버전을 전진시킨다. 끝난 실행은 최근 128개까지만 남기며, 지워진 run id를 재사용해도 예전 binding id의 답·중단·완료 요청을 받아들이지 않는다.
- 대상/참고의 수동 변경·닫기·실행기 교체는 진행 중/대기 중 바인딩을 무효화한다. 중단·시간 초과·패널 닫기도 마찬가지다. 실패한 편집을 자동 재전송하지 않는다. 편집기 자체에서도 실제 적용 직전에 ticket의 버전·선택과 abort를 다시 검사해야 한다. 응답을 버리는 것만으로 이미 적용된 편집을 막았다고 주장할 수 없다.

[`workspace-ai-run-registry.test.ts`](../../apps/shell/tests/workspace-ai-run-registry.test.ts)는 합성 endpoint로 이 경계를 검사한다. 실제 도구 실행·제공자 호출·파일 저장은 하지 않는다. 무효화는 동기 `onStopped` 알림으로 전달하며, `state`나 `claimTool`이 시간 초과를 발견했을 때도 알림을 잃지 않는다. 호스트가 생기면 이 알림에서 transport와 editor 작업을 함께 중단하고, 타이머로 timeout을 처리하는 배선도 별도로 검증한다. 이 모델 자체가 하위 프로세스를 종료하지는 않는다.

## 구현된 편집기 실행 통신

`packages/agent-core`의 `workspace-adapter.ts`는 현재 문서·선택 스냅숏·읽기·준비된 실행의 공통 경계다. 준비된 실행은 허용한 로컬 도구만 내놓고 참고 문서는 읽기 전용이다. 호출 인자를 복사하고 기존 루프의 스키마 검사도 사용한다. 첫 쓰기 전과 비동기 확인 뒤에 버전·읽기 전용·중단을 다시 확인한다. 호출 번호는 한 번만 소비하며, 준비·실행 중 취소한 일이 실제로 끝나기 전에 다음 준비를 받지 않는다. 실행 핸들은 어댑터마다 다른 무작위 식별자를 가져 새로 뜬 편집기의 실행과 겹치지 않는다.

- **DOCX·ODT:** 기존 skill의 본문 읽기·편집·차트·변경 내용을 연결했다. 캡처한 ProseMirror 선택을 자기 편집을 따라 옮기며 ODT 도구 필터를 유지한다. 메모·각주·머리말·꼬리말 같은 별도 저장소와 긴 글 작성기·그림·파일·네트워크는 아직 내놓지 않는다. 알려진 가리기는 현재 모델용 글로 투영하고, 안전하게 다룰 수 없는 가림·삭제 미리보기와 가린 문서의 추적 편집은 쓰기 전에 거절한다.
- **Markdown:** 기존 skill의 문서·블록·frontmatter 읽기와 연산을 연결했다. 원문 모드는 거절하고, 문서 재읽기와 본문·frontmatter 변경을 구분한다. 선택을 잠깐 복원할 때 사람의 커서와 입력 서식을 돌려놓는다. 가린 본문은 기존 투영을 사용하며, 가린 표시가 든 YAML은 기존 `read_frontmatter`와 어댑터 모두 거절한다. 파일과 YAML을 자동 수정하지 않는다. 그림·긴 글 작성기·파일·네트워크는 내놓지 않는다.
- **HWP·HWPX:** 기존 skill과 플러그인을 사용한다. 플러그인의 `workspaceSnapshot`·`workspaceInvoke`가 실제 동작과 같은 차례에 문서 세대와 변경 버전을 확인한다. 메모 삭제 확인 뒤의 재시도도 같은 검사를 지나며 중단하면 확인 카드도 닫는다. 가리기 표시 기능이 없으므로 읽기에 `masking: 'unsupported'`를 명시한다. 파일·그림·네트워크는 내놓지 않는다.

`workspace-editor-protocol.ts`의 `workspace-ai:editor-request / editor-reply / editor-cancel`만 전용 preload가 다룬다. 렌더러가 다른 문서나 메인 채널을 임의로 호출하는 API는 없다. `hostWorkspaceEditor`가 편집기 안에서 준비·실행·응답 검사·해제를 받고, 기존 편집기 패널이 실행 중이면 거절한다. 파일 열기와 호스트 설치 자체는 내용을 읽거나 모델을 부르지 않는다.

메인의 `WorkspaceEditorConnection`은 실제 보기 객체·최상위 프레임·요청 번호와 답의 모양을 검사한다. 호출자 중단은 해당 요청의 취소를 편집기로 전하고, 실행 제어기가 그 실행의 종료 완료를 기다린다. 시간 초과·본문 이동·렌더러 종료는 연결 자체를 무효화한다. 기다리는 도구를 자동 재전송하지 않는다. `TabManager.workspaceEditorForTab`은 같은 창에 이미 불러온 지원 문서만 내주고, 복구 탭을 자동으로 열지 않는다. 탭 닫기·떼어내기는 연결을 해제한다. **실행 바인딩 모델은 아래 제어기로 연결했고, 실행 호스트도 가짜 모델로 검사했다. 기본 화면의 공용 패널과 실제 구독 전송은 아직 연결하지 않았다.** 실제 모델 전송을 켜기 전에 아래 보안·동의와 대화 수명 작업을 끝내야 한다.

## 공용 패널에 연결하기 전에 남은 필수 작업

공간 모델도 아직 호스트 배선을 대신하지 않는다. `TabManager.setWorkspacePanel()`로 예약할 때는 main이 계산한 문서 사각형을 `AppFrame`의 `viewport.documents`에 함께 전달해야 한다. 현재 `AppFrame`은 패널이 없는 기본 영역을 쓰고, non-null 예약을 부르는 실제 호스트도 없다. 그 상태에서 main만 예약하는 호출을 먼저 추가하면 구분선과 드래그 좌표가 어긋난다. 시제품은 같은 문서 사각형을 양쪽에 전달해 이 경계를 검사한다.

1. **현재 자료 읽기와 가리기:** HWP·DOCX·Markdown의 전용 현재 읽기는 구현·검사했다. 다른 형식의 읽기와 모델 전송을 켜는 배선은 남았다. 기존 첨부/프로젝트 읽기는 저장 안 된 문서를 거절하며 공개 MCP 읽기는 가리기를 적용하지 않는다([보안 정책](../security.md)의 "문서 내용"). 그 경로를 새 실시간 참고 기능으로 그대로 쓰면 안 된다. 각 편집기가 가린 현재 자료·범위·버전을 내주는 전용 읽기 snapshot을 구현하고, 읽기 실패면 적용 전 멈춘다. 디스크 fallback·자동 저장은 없다. 지원하지 않는 형식은 이유를 보인다. 이 기능을 켤 때 보안 정책·PRIVACY·첫 연결 안내에 새로 읽는 범위를 맞춘다.
2. **DOCX·Markdown·HWP 실행기:** 위에 적은 로컬 도구와 전용 통신은 구현·검사했다. 실행 바인딩 모델과의 연결은 끝났으며, DOCX·Markdown의 전체 실행 되돌리기 토큰·카드는 아래 경로로 구현했다. 문서별 별도 저장소·긴 글 작성기·HWP 실행 전체 되돌리기의 이행은 남았다. 기존 skill·선택·도구 검사·실행 취소·확인·긴 글 작성기·`verifyResponse`를 어댑터로 연결한다. 가짜 모델의 같은 입력으로 기존 실행기와 결과를 비교한다. 실제 적용 직전 버전/선택 재검사와 중단을 통과해야 한다.
3. **대화 컨트롤러와 보관 연결:** 아래 상태·보관 연결은 구현하고 합성 실행으로 검사했다. 공용 호스트에서 실제 출처 목록·홈 기록 원천·공유 로컬 서비스와 연결하고, 실행기·카드·원격 프로젝트 기록 갱신을 이행하는 작업은 남았다.
4. **공용 패널과 전수 이행:** 1~3의 검증 뒤 셸 패널을 켜고, 이행한 편집기에서만 중복 패널을 끈다. 모든 형식이 준비된 뒤 기본 화면에서 공용 구조를 완성한다. 홈/발표/인쇄 미리보기와 떼어 낸 창은 각각의 수명을 검사한다.
5. **실제 확인:** 현재 소스로 만든 앱에서 두 방향 분할과 UI 배율·테마·작은 창을 확인하고, 가짜 응답 지연·선택 변경·탭 닫기/새로고침·복구·기존 기록을 검사한다. Windows 설치본 사람 확인, Mac/Linux 자동 검사와 보고 범위를 따로 기록한다. 이 문서의 코드 조사는 설치본 확인 결과가 아니다.

## 메인 실행 제어기

`main/workspace-ai/execution-controller.ts`의 `WorkspaceExecutionController`가 registry와 준비된 편집기 세션을 잇는다. `TabManager.workspaceAiForPanel`은 실제 창과 패널 webContents로 소유자를 정하고, 증가하는 패널 세대마다 하나만 만든다. 패널 본문 이동·렌더러 종료·창 닫기는 제어기를 해제한다. 이전 세대로 되돌리거나 이전 소유자의 실행 핸들을 쓰면 거절한다. 기본 화면에서 이 팩터리를 호출하거나 모델 전송을 시작하는 코드는 아직 없다.

1. **캡처:** 같은 창의 이미 불러온 지원 보기에서 `describe`를 받는다. 이 요청은 문서 버전·선택의 불투명 식별자·도구 권한의 상한·가리기와 변경 알림 지원 여부만 받고, skill이나 문맥을 만들지 않는다. 메인은 창·탭·편집기 instance·새 세대와 함께 캡처 식별자를 발급한다. 변경 알림을 지원하지 않는 실행기는 연결하지 않는다. ODT 등 실제 지원 도구는 실행 직전 준비된 세션에서도 다시 확인한다.
2. **참고 취득:** 캡처 식별자와 명시한 `document / selection` 범위를 전용 읽기에 넘긴다. 본문은 그때 처음 읽는다. 결과는 범위·버전·가리기 지원·잘림 표시를 가진 별도 snapshot이다. 참고를 위해 skill 문맥을 만들거나 다른 블록을 추가로 읽는 native 도구를 내놓지 않는다. 스냅숏은 저장 전 자료이며 디스크 fallback이나 자동 저장은 없다.
3. **대기열:** 사람이 보낸 요청은 캡처/참고 식별자만으로 대상을 고른다. 메인이 보관한 snapshot과 프로젝트 정체를 registry에 복사한다. 캡처는 최근 128개, 참고 snapshot은 최근 32개까지만 찾을 수 있고, 이미 들어간 요청은 자기 사본을 유지한다. 요청 하나의 참고는 20개·합계 200,000자 이내다. 넘으면 조용히 버리지 않고 거절한다. 창의 대기열 상한은 기존 32개다.
4. **준비·도구:** FIFO에서 하나를 꺼내 대상과 참고의 실제 버전을 재확인한 뒤 대상 skill만 준비한다. 반환하는 참고 자료는 명시적으로 읽은 범위뿐이다. 도구 호출은 소유 창·패널 세대·대화·실행·binding 번호, registry ticket, 실제 준비된 도구 목록과 선택을 확인한다. 다른 문서나 참고 문서에 대한 쓰기는 실행되지 않는다. 대상 쓰기의 검증된 답만 registry의 버전을 전진시키고, 같은 문서의 오래된 대기 요청은 중단한다. 실제 편집 직전 검사는 기존 편집기 어댑터가 계속 맡는다.
5. **변경·종료:** `workspace-ai:editor-event`는 호스트 정체와 준비/변경/해제만 보내며 문서 내용이나 경로가 없다. DOCX 본문, Markdown 본문·frontmatter·원문 모드·재읽기, HWP 플러그인 문서 변경을 전한다. 참고 변경이나 실행기 소실은 진행 중 요청의 중단 신호를 끊는다. 대상 도구가 낸 자기 변경은 검증된 답으로만 인정한다. 시간 초과는 타이머로도 발견하고, 실패한 편집은 재전송하지 않는다.
6. **취소 완료 대기:** 편집기에는 각 바인딩마다 별도의 무작위 실행 id를 준다. 대화나 패널의 run id가 나중에 재사용돼도 예전 정리 요청이 새 일을 끝낼 수 없다. `settle`은 그 실행의 준비·도구·응답 검사를 취소한 뒤 실제로 끝나야 답한다. 제어기는 이 답을 기다린 뒤 다음 요청을 준비한다. 다른 대화의 취소가 현재 실행을 해제하지 않는다.

제어기는 제공자·구독 프로그램·파일·공개 MCP·대화 저장소를 호출하지 않는다. 아래 실행 호스트는 기존 보내기 문지기·프로젝트 믿음/권한·transport를 주입받는 구조다. 기본 화면을 켤 때는 이 주입 자리에 실제 기존 서비스를 연결해야 한다. `onStopped`와 `signal`만 있는 현재 코드를 실제 구독 프로세스 종료 검증으로 해석하지 않는다.

## 대화별 상태와 기록 연결

`renderer/src/workspace-ai/conversations.ts`의 `WorkspaceConversations`는 출처별로 이력·초안·첨부·스킬 칩·대상·참고·프로젝트·스크롤·MCP 선택·대기 요청·허락·오류와 별도 실행기를 소유한다. 실행기는 호스트가 대화마다 한 번 만든다. 열기와 선택은 전송·중단·허락 승인을 하지 않으며, 같은 출처를 다시 열어도 실행기와 초안을 교체하지 않는다. 기존 기록의 제공자·모델이나 프로젝트 출처는 현재 설정·믿음을 바꾸지 않는다. 기존 첫 저장/이동 서비스가 돌려준 참조는 `rebindLegacy`로 갱신하며, 실행 중인 대화 id·실행기·초안·허락을 유지한다. 서로 열린 두 기록을 이 경로로 합치지는 않는다. 호스트는 기록할 때 이 최신 출처를 사용해야 한다.

사람이 보낸 요청의 입력은 대기할 때 복사한다. 콜백과 허락 답은 컨트롤러 instance·대화·실행 id·증가하는 실행 세대로 검사하며, 취소 후 같은 run id를 써도 옛 콜백은 거절한다. 취소/해제 시 답하지 않은 허락은 거절하고 해당 실행의 신호를 끊는다. 이 컨트롤러는 화면 상태의 소유자다. FIFO 순서와 편집기 취소 완료 대기, 모델 호출 전 보내기 판단은 메인 제어기와 호스트가 계속 맡는다.

`main/workspace-ai/conversation-history.ts`의 `WorkspaceConversationHistory`는 주입받은 기존 `ProjectStore`와 `ProjectChatStore`를 사용한다. 문서 기록은 안정적인 `projectId/chatId` 참조를 따라 읽고 쓴다. 프로젝트 기록은 기존 `openChat/append`를 거쳐 다른 PC 표시와 쓰기 거절을 그대로 전한다. 명시적으로 새로 만든 프로젝트 대화는 첫 답 전에 파일이 없어도 빈 기록/첫 메시지 버퍼로 열 수 있다. 프로젝트 쓰기가 막히면 로컬 대화로 대신 저장하지 않는다. 홈의 임시 기록은 창 세션과 대화 id로 나누고, `attachMemory`로 원래 홈 호스트의 읽기/쓰기 원천을 연결한다. 본문 복사·자동 병합·문서 닫기에 따른 기록 삭제는 없다.

이 부품들은 **공용 패널 IPC나 기본 화면에 등록하지 않았다.** 실제 `AgentLoop` 두 개와 가짜 transport로 대화 전환 중 응답·이력 격리를 검사했고, 임시 로컬 저장소로 재시작 복원·크기 제한·잘못된 버전·기존 문서 첫 저장/이름 변경 후 기록 연결을 검사했다. 기존 프로젝트 기록의 전체 검사도 함께 통과했다. 실제 모델·사용자 문서·Windows 설치본 검증은 아니다.

## 공용 실행 호스트와 카드

`renderer/src/workspace-ai/run-host.ts`의 `WorkspaceRunHost`는 대화별 `AgentLoop`를 메인 실행 제어기에 연결한다. 명시적 전송의 초안·대상 캡처·참고 snapshot·프로젝트를 고정하고 FIFO로 실행한다. 모델에 내놓는 문서 도구는 준비된 대상의 목록뿐이다. 참고는 명시적으로 읽은 가린 snapshot과 범위·문서 정체·버전만 문맥에 넣고, 문서 디스크 읽기나 저장으로 대신하지 않는다. 실행기에는 대상 도구와 메인의 비동기 응답 검사를 그대로 호출한다.

보내기 판단은 `useAiSendGate.admit/admitQueued`와 현재 `gate`를 주입하는 자리다. 처음 붙잡힌 요청은 원래 `WorkspacePendingSend`를 `resume`으로 돌려주므로, 그사이 다른 대화를 고르거나 초안을 고쳐도 이전 요청의 대상이 바뀌지 않는다. 대기 중 확인/안내를 기다리면 요청을 유지하고 `wake` 때 다시 판단한다. 연결 불가면 중단하며, 준비 뒤에도 다시 판단한다. `prepare`는 기존 프로젝트 믿음·첨부·사용자 스킬·드라이브·인터넷/MCP 경계를 연결하는 필수 자리다. 반환한 프로젝트 id/문맥 버전이 대기 바인딩과 다르면 보내지 않는다. **이 주입 자리에 실제 기본 화면의 서비스와 구독 전송을 연결한 상태는 아니다.**

`WorkspaceRunCards.tsx`는 기존 `McpPermissionPrompt`를 쓴다. 대화마다 다른 허락 저장소를 유지하며, 표시한 대화만 바꾸는 것은 거절이나 승인으로 처리하지 않는다. 실행 중단·호스트 해제는 기다리는 허락을 거절한다. 표시 문구는 기존 21개 언어 자원을 사용하는 호스트가 넘긴다. 종료 시에는 편집기 작업뿐 아니라 이전 transport/루프의 취소 완료도 기다린 뒤 같은 대화의 실행기를 다시 쓴다. 기록 쓰기 실패는 화면에 남기고 재시도·로컬 대체 저장·모델 재전송을 하지 않는다.

전체 실행 되돌리기는 문서 내용을 패널에 보내지 않는다. `workspace-adapter.ts`가 첫 쓰기 직전 편집기 안에 스냅숏을 한 번 잡고 검증된 변경마다 버전을 전진시킨다. 편집기·메인은 최근 16개 토큰만 보관한다. 메인은 별도의 소유자/대화/실행/binding 토큰을 내주고, 실행이 끝난 뒤 같은 문서 인스턴스·버전·읽기 전용 여부를 확인해 복원을 한 번만 전달한다. 수동 변경·다른 문서·새 세대·재사용·실행 중 복원은 거절한다. DOCX는 기존 `rollback-snapshot.ts`, Markdown은 기존 본문/frontmatter `getSnapshot/restoreSnapshot`을 쓴다. HWP의 실행 전체 되돌리기는 아직 이 경로에 연결하지 않았다.

비동기 응답 검사를 위해 `AgentSkill.verifyResponse`는 Promise도 받을 수 있다. 기존 동기 검사는 같은 순서로 동작한다. 검사 중 취소는 루프를 끝내고 세대를 바꿔, 늦은 검사 성공/실패가 다음 실행을 건드리지 못하게 한다. 이 경로는 공통 실행부 전체 검사와 가짜 transport로 확인했다. 빌드한 앱에서는 저장 전 Markdown 자료로 DOCX를 고친 뒤 토큰으로 원래 본문을 복원했고, 다른 대화의 메시지와 원본 파일 세 개는 바뀌지 않았다. 실제 모델 호출은 0건이다.

## 공용 패널과 선택적 셸 배치

`WorkspacePanelController`는 기존 `WorkspaceRunHost.conversations`를 사용한다. 출처 목록 갱신·대화 선택·문서 초점 변경은 읽기나 전송을 시작하지 않는다. 새 대화의 최초 대상만 클릭 당시의 초점 문서를 제안하고, 기존 대화의 대상은 자동으로 채우지 않는다. 대상/참고 취득의 늦은 답은 대화와 동작 세대로 구분하며, 대상 변경 실패 뒤 이전 문서에 보내는 길은 막는다. 참고는 명시한 범위로 취득하고, 패널에는 본문 대신 식별자/바인딩만 전달한다. 이력 출처와 실제 `capture/reference/create` 서비스는 호스트가 주입한다. 기본 화면의 IPC에는 아직 등록하지 않았다.

`WorkspacePanel`은 21개 언어의 대화/대상/참고 선택기, 초안과 스크롤 복원, 기존 작성기/허락/되돌리기 카드와 접힌 레일의 작업 중단을 그린다. 화면이 받는 실행 식별자는 복사본이므로 중단은 객체 참조 대신 컨트롤러·대화·실행·세대 네 값으로 검사한다. `AiComposer.sendDisabled`는 문서 바인딩이 준비되지 않아도 글쓰기는 허용하고 전송/대기열 추가만 막는다. 패널을 숨기거나 다른 대화를 선택하는 동작은 호스트를 해제하지 않는다.

`AppFrame.workspace`는 선택적 마운트 계약이다. 실제 호스트는 main의 `TabManager.setWorkspacePanel()` 예약이 끝난 뒤 반환하는 `workspaceBounds()`를 전달하고, 크기·배율·분할·발표 상태가 바뀌면 같은 영역을 갱신해야 한다. `AppFrame`은 그 문서 사각형을 홈/구분선에 전달하고, 패널은 확대 틀 밖 포털에서 같은 좌표를 쓴다. 발표 중의 bounds는 패널 숨김을 반환하며 원래 예약 선호는 유지한다. 탭 표시줄의 공용 AI 토글도 이 계약이 있을 때만 나타난다. **일반 시작 경로는 이 계약을 주입하지 않는다.** 합성 네이티브 화면 시험은 실제 서비스·구독·문서 엔진의 패널 통합 시험을 대신하지 않는다.

## 다음에 이어갈 지점

3단계의 실제 셸 호스트와 IPC에 위 패널을 연결한다. 내부 실행 호스트·카드는 위 경로로 연결했으며, 실제 출처 목록·프로젝트 선택/믿음·기존 공유 기록 서비스·구독 전송을 붙이는 작업이 남았다. main의 예약 영역 갱신을 실제 IPC로 `AppFrame`에 전달하고, 구현한 대상·참고·대화 선택기를 실제 출처 목록에 연결해야 한다. 별도 문서 저장소·긴 글 작성기·HWP 전체 실행 되돌리기·사용량 표시와 나머지 형식의 이행도 남았다. 실제 참고 읽기를 켜기 전에 보안 정책·PRIVACY·첫 연결 안내의 읽기 범위도 맞춘다. 공용 패널이 동작하기 전에 기존 AI 입구를 없애지 않는다.
