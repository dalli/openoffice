# 작업 화면 개편: 연결 계약과 이행 순서

상태: **HWP·DOCX·Markdown 어댑터와 전용 통신·메인 실행 제어기, 대화별 상태/기록·준비 서비스·기존 AI 전송·기본 창 호스트 구현**(2026-11-06). [전체 계획](workspace-ui.md)의 대화 선택 요구를 기준으로 현재 코드와 이행 경계를 정리했다. 기본 창의 탭 표시줄에서 공용 패널을 열 수 있다. 기존 편집기 AI 창과 대화 보관은 유지하며, 워드 긴 글 작성기·빠른 작업과 기존 리본/메뉴 시작점을 연결했으며 선택 편집 대기열 카드·묶음 실행과 프로젝트 안팎의 워드 양식 사본 요청도 연결했다. 양식 비우기 미리보기·그림/매체·나머지 형식의 이행과 Windows 설치본 확인은 남았다.

## 이번 구현에서 쓰는 기본안

- 대상과 참고 문서는 **같은 창**의 열린 문서로 한정한다. 경로·제목·좌우 위치는 사람이 고르는 표시이고, 실행 정체는 창·탭·문서 인스턴스·편집기 세대다. 같은 파일의 두 사본은 서로 다른 인스턴스다. 떼어 낸 창과 독립 편집기는 기존 AI 창을 유지하고 다음 이행 단계에서 자기 도우미를 붙인다. 다른 창에 접근하는 길은 만들지 않는다.
- **창마다 실행 하나**를 우선 지원한다. 다른 대화는 열어 읽고 초안을 쓸 수 있으며, 사람이 보낸 요청은 실행 당시의 대상·선택·참고·프로젝트를 담아 FIFO로 기다린다. 대기 중 문서가 바뀌면 그 요청을 멈추고 다시 검토하게 한다. 이전 요청이 같은 문서를 고친 경우도 해당한다. 대화 선택만으로 실행·중단·권한 승인·자동 재전송을 하지 않는다.
- 패널 공간과 문서 분할은 별도 상태다. 기존 좌우·너비 설정을 덮어쓰지 않고 좁은 창에서만 잠깐 접는다. 실제 문서 뷰 위에 DOM을 겹치는 대신 메인의 문서 사각형을 줄인다. 기본 창에서는 준비된 서비스 호스트가 열릴 때만 공간을 예약하고, 접으면 공간을 돌려준다.
- 기본안의 범위·직렬 실행 정책을 바꿀 때는 새 결정 기록을 남긴다. 결정 0037의 역사와 기존 독립 편집기 동작을 지우지 않는다. 공용 패널이 완성되기 전에 편집기 안 AI 진입점을 없애지 않는다.

## 현재 연결 구조와 넘겨야 하는 것

[AgentSkill](../../packages/agent-core/src/skill.ts)은 도구·지시문·문맥·실행기와 `verifyResponse`를 묶는다. [AgentLoop](../../packages/agent-core/src/loop.ts)는 인자 검사·호출 순서·중단·응답 검사를 맡는다. 공용 패널을 만들 때는 이 계약의 일부만 옮기지 않는다. 각 편집기의 엔진과 DOM은 원래 렌더러에 두고, 문서 실행기는 도구 실행·선택 검사·변경 표시·되돌리기와 부분 결과 유지/버리기를 계속 맡는다.

## 빠른 작업의 현재 실행 방식

2026-11-05 공용 패널 연결: DOCX/ODT 대상에 네 작업을 제공한다. 기존 21개 언어의 이름·요약/서식/마인드맵 지시를 재사용하고, 다듬기는 원래 범위가 있으면 그 부분을 쓰는 문구를 21개 언어로 제공한다. `WorkspacePanelController.preset`은 대화의 글만 바꾸며 캡처·재선택·참고 읽기·전송을 하지 않는다. 보내기·대기열은 원래 경로를 쓴다. `generate_mindmap`은 기존 로컬 읽기 도구이며 문서 버전·저장 상태·되돌리기를 바꾸지 않는다. `WorkspaceRunHost`가 대화마다 최근 16개 카드와 원래 대상 정체만 창 메모리에 보관하고, 기존 마인드맵 뷰를 재사용한다. 나무를 도구 결과의 표시 외에 모델 이력·저장 메시지로 복사하지 않는다. 다른 대화로 늦은 결과를 보내지 않고, 대상 인스턴스·세대가 달라지면 노드 질문을 끈다. 문서 위치 이동·문서에 그림 넣기는 이 공용 카드에서 제공하지 않으며 도구 설명/결과도 이를 약속하지 않는다. 기존 편집기 레일은 선택 편집 대기열·그림/매체 등 나머지 기능의 이행 전까지 유지한다.

## 대화 보관과 이전 계약

현재 대화는 한 저장소에 있지 않다.

1. **기존 문서별 기록:** [`ProjectStore`](../../packages/project-store/src/store.ts)의 `resolveChatForFile`, `chatIdByPath`, `rebindChat`와 편집기 `window.projectApi`를 쓴다. 처음에는 경로 해시를 쓰지만 한 번 등록한 chat id는 이름 변경/이동을 따라 안정적으로 유지한다. 제목 없는 기록은 `unsaved-*`이고 첫 저장에서 기존 rebind 경로를 지난다. 새 화면이 새 경로 해시로 기록을 다시 만들지 않는다.
2. **프로젝트 대화:** [`ProjectChatStore`](../../apps/shell/src/main/projects/chat-store.ts)가 `.ieumoffice/chats/<id>.json`과 `<id>.jsonl`을 다룬다. 프로젝트 믿음·외부 PC 기록·쓰기 확인·원자적 정보 저장·동일 대화 직렬 쓰기를 지킨다. [`useProjectChat`](../../packages/ui/src/use-project-chat.ts)의 기존 문서 기록과 프로젝트 기록 구분을 유지한다.
3. **홈 질문:** [`KbAskPanel`](../../apps/shell/src/renderer/src/KbAskPanel.tsx)은 프로젝트를 고르지 않았으면 메모리에만 있고, 프로젝트를 고르면 해당 프로젝트 대화에 보관한다. 별표 그룹으로 좁힌 읽기 범위도 별도다.

공용 선택기는 위 기록을 **출처 참조**로 열어야 한다. `WorkspaceConversationOrigin`이 `legacy-document / project / window-memory / workspace`를 구분한다. 기존 JSONL을 복사·합치거나 문서 닫기 때문에 지우지 않는다. 가져온 대화의 제공자/모델은 기록일 뿐 현재 설정을 바꾸는 명령이 아니다. 기존 MCP의 "이 대화에서 항상 허용"과 서버 끄기 상태도 다른 대화에 옮기지 않는다.

새 다중 문서 대화는 파일 한 개의 경로로 id를 만들지 않고 별도의 무작위 id를 쓴다. 프로젝트를 고른 대화는 기존 프로젝트 파일 형식과 쓰기 함수를 사용한다. `ProjectStore`에 프로젝트 없는 새 대화의 분기를 추가했다. `<userData>/projects/.workspace/v1/<id>.json`은 버전·무작위 id·제목·생성 시각, 같은 이름의 `.jsonl`은 기존과 같은 메시지 형식이다. 기존 JSONL 쓰기·읽기 코드와 크기 제한·첫 답 전 버퍼를 공유하고 문서 경로 맵이나 프로젝트 목록에는 등록하지 않는다. 모르는 정보 버전은 덮어쓰지 않고 거절한다. 이 분기는 기본 창의 새 공용 대화에서도 사용하며 자동 이전은 없다. 사용자 폴더, 세션 기록, 복구 사본 또는 설정 파일에 대화 본문을 끼워 넣지 않는다.

선택한 대화마다 다음 상태를 따로 소유해야 한다: 이력과 AgentLoop, 작성 중 글·첨부·스킬 칩, 명시한 참고·수정 대상, 프로젝트, 스크롤, 실행·대기열, 허락 카드와 중단 신호. 탭 선택은 이 객체를 교체하는 이벤트가 아니다. 새 대화에서만 현재 문서를 최초 대상의 제안으로 쓴다. 기존 `useProjectChat.openChat`은 화면 전체의 메시지를 교체하는 경로이므로, 한 패널 인스턴스를 재사용하며 실행 중인 대화의 상태까지 바꾸는 식으로 곧바로 연결하면 안 된다.

## 구현된 실행 바인딩 모델

[`workspace-ai-api.ts`](../../apps/shell/src/shared/workspace-ai-api.ts)와 [`run-registry.ts`](../../apps/shell/src/main/workspace-ai/run-registry.ts)는 Electron 없이 검사할 수 있는 **미등록 내부 모델**이다.

- 소유자는 창 id·패널 webContents id·패널 세대다. 편집기 endpoint는 main이 알려진 live view에서 등록한다. 패널이 보내는 경로나 webContents 번호로 endpoint를 만들어 주지 않는다.
- 요청은 `conversationId`, `runId`, 대상의 문서 정체·세대·버전·선택 스냅숏, 명시적으로 취득한 참고 snapshot id·버전, 준비한 프로젝트 정체/문맥 버전을 복사해 보관한다. main은 별도의 단조 증가 `bindingId`를 발급한다. enqueue 이후 작성기 값을 바꿔도 바인딩은 바뀌지 않는다.
- 실행은 창마다 하나이며 대기열은 FIFO다. 실행 모델의 `startNext`는 모델을 호출하지 않는다. 호스트가 실행 직전 기존 `useAiSendGate`/제공자 선택과 준비 결과를 확인한 다음 시작해야 한다. 대기열 수용도 그 판단을 우회하지 않는다.
- 도구 ticket은 허용한 문서 도구 이름·읽기/쓰기·정체·세대·버전·선택만 담는다. 임의 채널 호출이나 JavaScript 실행은 없다. 참고 endpoint에 쓰기 도구가 등록돼 있어도 참고 바인딩으로는 쓸 수 없다. 요청에 없는 C 문서에 접근할 수 없다.
- 한 실행에서 도구 호출 하나만 진행하고 call id를 한 번만 소비한다. 답은 실제 IPC sender와 원래 패널 세대·대화·실행·binding id·호출·도구·문서 세대가 모두 맞아야 받아들인다. 읽기 답이 문서를 바꾸거나 버전을 바꾸면 실패한다. 검증된 대상 쓰기만 자기 버전을 전진시킨다. 끝난 실행은 최근 128개까지만 남기며, 지워진 run id를 재사용해도 예전 binding id의 답·중단·완료 요청을 받아들이지 않는다.
- 대상/참고의 수동 변경·닫기·실행기 교체는 진행 중/대기 중 바인딩을 무효화한다. 중단·시간 초과·패널 닫기도 마찬가지다. 실패한 편집을 자동 재전송하지 않는다. 편집기 자체에서도 실제 적용 직전에 ticket의 버전·선택과 abort를 다시 검사해야 한다. 응답을 버리는 것만으로 이미 적용된 편집을 막았다고 주장할 수 없다.

[`workspace-ai-run-registry.test.ts`](../../apps/shell/tests/workspace-ai-run-registry.test.ts)는 합성 endpoint로 이 경계를 검사한다. 실제 도구 실행·제공자 호출·파일 저장은 하지 않는다. 무효화는 동기 `onStopped` 알림으로 전달하며, `state`나 `claimTool`이 시간 초과를 발견했을 때도 알림을 잃지 않는다. 호스트가 생기면 이 알림에서 transport와 editor 작업을 함께 중단하고, 타이머로 timeout을 처리하는 배선도 별도로 검증한다. 이 모델 자체가 하위 프로세스를 종료하지는 않는다.

## 구현된 편집기 실행 통신

`packages/agent-core`의 `workspace-adapter.ts`는 현재 문서·선택 스냅숏·읽기·준비된 실행의 공통 경계다. 준비된 실행은 허용한 로컬 도구만 내놓고 참고 문서는 읽기 전용이다. 호출 인자를 복사하고 기존 루프의 스키마 검사도 사용한다. 첫 쓰기 전과 비동기 확인 뒤에 버전·읽기 전용·중단을 다시 확인한다. 호출 번호는 한 번만 소비하며, 준비·실행 중 취소한 일이 실제로 끝나기 전에 다음 준비를 받지 않는다. 실행 핸들은 어댑터마다 다른 무작위 식별자를 가져 새로 뜬 편집기의 실행과 겹치지 않는다.

- **DOCX·ODT:** 기존 skill의 본문 읽기·편집·차트·변경 내용을 연결했다. 캡처한 ProseMirror 선택을 자기 편집을 따라 옮기며 ODT 도구 필터를 유지한다. App의 `DocsReviewStore`와 기존 검토 실행기를 연결해 메모 읽기·넣기·답글·해결·삭제와 각주/미주 읽기·넣기·수정·삭제도 제공한다. 목록만 바뀌어도 문서 버전을 전진시키며 첫 쓰기 전 본문과 목록을 함께 보관한다. 명시한 참고 읽기에 이 목록을 더하지는 않는다. 머리말·꼬리말·쪽 설정·스타일·워터마크도 App의 `DocsLayoutStore`와 기존 실행기로 연결했다. 본문 밖 변경을 같은 버전·전체 되돌리기에 포함하며, 공용 구역 나누기는 자동 저장을 예약하지 않는다. 저장으로 parsed 기준이 바뀌면 이전 복원을 거절한다. 긴 글 작성기는 아래 내부 통신으로 연결했으며 그림·파일·네트워크는 아직 내놓지 않는다. 알려진 가리기는 현재 모델용 글로 투영하고, 안전하게 다룰 수 없는 가림·삭제 미리보기와 가린 문서의 추적 편집은 쓰기 전에 거절한다.
- **Markdown:** 기존 skill의 문서·블록·frontmatter 읽기와 연산을 연결했다. 원문 모드는 거절하고, 문서 재읽기와 본문·frontmatter 변경을 구분한다. 선택을 잠깐 복원할 때 사람의 커서와 입력 서식을 돌려놓는다. 가린 본문은 기존 투영을 사용하며, 가린 표시가 든 YAML은 기존 `read_frontmatter`와 어댑터 모두 거절한다. 파일과 YAML을 자동 수정하지 않는다. 그림·긴 글 작성기·파일·네트워크는 내놓지 않는다.
- **HWP·HWPX:** 기존 skill과 플러그인을 사용한다. 플러그인의 `workspaceSnapshot`·`workspaceInvoke`가 실제 동작과 같은 차례에 문서 세대와 변경 버전을 확인한다. 메모 삭제 확인 뒤의 재시도도 같은 검사를 지나며 중단하면 확인 카드도 닫는다. 가리기 표시 기능이 없으므로 읽기에 `masking: 'unsupported'`를 명시한다. 파일·그림·네트워크는 내놓지 않는다.

`workspace-editor-protocol.ts`의 `workspace-ai:editor-request / editor-reply / editor-cancel`만 전용 preload가 다룬다. 렌더러가 다른 문서나 메인 채널을 임의로 호출하는 API는 없다. `hostWorkspaceEditor`가 편집기 안에서 준비·실행·응답 검사·해제를 받고, 기존 편집기 패널이 실행 중이면 거절한다. 파일 열기와 호스트 설치 자체는 내용을 읽거나 모델을 부르지 않는다.

메인의 `WorkspaceEditorConnection`은 실제 보기 객체·최상위 프레임·요청 번호와 답의 모양을 검사한다. 호출자 중단은 해당 요청의 취소를 편집기로 전하고, 실행 제어기가 그 실행의 종료 완료를 기다린다. 시간 초과·본문 이동·렌더러 종료는 연결 자체를 무효화한다. 기다리는 도구를 자동 재전송하지 않는다. `TabManager.workspaceEditorForTab`은 같은 창에 이미 불러온 지원 문서만 내주고, 복구 탭을 자동으로 열지 않는다. 탭 닫기·떼어내기는 연결을 해제한다. **실행 바인딩 모델과 실행 호스트를 연결했고 기본 창에서도 기존 문지기를 거쳐 전송한다.** 실제 구독 프로세스와 Windows 설치본 확인은 남았다.

## 공용 패널로 완전히 이행하기 전에 남은 필수 작업

공간 모델도 아직 호스트 배선을 대신하지 않는다. `TabManager.setWorkspacePanel()`로 예약할 때는 main이 계산한 문서 사각형을 `AppFrame`의 `viewport.documents`에 함께 전달해야 한다. 기본 창의 `WorkspaceAppFrame`은 main이 확인한 영역을 `AppFrame`에 공급한다. 그 상태에서 main만 예약하는 호출을 먼저 추가하면 구분선과 드래그 좌표가 어긋난다. 시제품은 같은 문서 사각형을 양쪽에 전달해 이 경계를 검사한다.

1. **현재 자료 읽기와 가리기:** HWP·DOCX·Markdown의 전용 현재 읽기는 구현·검사했다. 다른 형식의 읽기와 모델 전송을 켜는 배선은 남았다. 기존 첨부/프로젝트 읽기는 저장 안 된 문서를 거절하며 공개 MCP 읽기는 가리기를 적용하지 않는다([보안 정책](../security.md)의 "문서 내용"). 그 경로를 새 실시간 참고 기능으로 그대로 쓰면 안 된다. 각 편집기가 가린 현재 자료·범위·버전을 내주는 전용 읽기 snapshot을 구현하고, 읽기 실패면 적용 전 멈춘다. 디스크 fallback·자동 저장은 없다. 지원하지 않는 형식은 이유를 보인다. 이 기능을 켤 때 보안 정책·PRIVACY·첫 연결 안내에 새로 읽는 범위를 맞춘다.
2. **DOCX·Markdown·HWP 실행기:** 위에 적은 로컬 도구와 전용 통신은 구현·검사했다. 실행 바인딩 모델과의 연결은 끝났으며, DOCX·Markdown·HWP의 전체 실행 되돌리기 토큰·카드는 아래 경로로 구현했다. DOCX의 메모·각주·미주 저장소도 연결했으며, 머리말·꼬리말·쪽 설정·스타일·워터마크 저장소도 연결했으며 긴 글 작성기도 아래 내부 통신으로 연결했다. 기존 skill·선택·도구 검사·실행 취소·확인·긴 글 작성기·`verifyResponse`를 어댑터로 연결한다. 가짜 모델의 같은 입력으로 기존 실행기와 결과를 비교한다. 실제 적용 직전 버전/선택 재검사와 중단을 통과해야 한다.
3. **대화 컨트롤러와 보관 연결:** 아래 상태·보관 연결은 구현하고 합성 실행으로 검사했다. 실제 출처 목록·공유 로컬 서비스는 전용 IPC에 연결했다. 홈 기록 원천·저장 전 문서 기록·기존 실행기와의 실시간 기록 갱신/이동 전달은 남았다.
4. **공용 패널과 전수 이행:** 1~3의 검증 뒤 셸 패널을 켜고, 이행한 편집기에서만 중복 패널을 끈다. 모든 형식이 준비된 뒤 기본 화면에서 공용 구조를 완성한다. 홈/발표/인쇄 미리보기와 떼어 낸 창은 각각의 수명을 검사한다.
5. **실제 확인:** 현재 소스로 만든 앱에서 두 방향 분할과 UI 배율·테마·작은 창을 확인하고, 가짜 응답 지연·선택 변경·탭 닫기/새로고침·복구·기존 기록을 검사한다. Windows 설치본 사람 확인, Mac/Linux 자동 검사와 보고 범위를 따로 기록한다. 이 문서의 코드 조사는 설치본 확인 결과가 아니다.

## 메인 실행 제어기

`main/workspace-ai/execution-controller.ts`의 `WorkspaceExecutionController`가 registry와 준비된 편집기 세션을 잇는다. `TabManager.workspaceAiForPanel`은 실제 창과 패널 webContents로 소유자를 정하고, 증가하는 패널 세대마다 하나만 만든다. 패널 본문 이동·렌더러 종료·창 닫기는 제어기를 해제한다. 이전 세대로 되돌리거나 이전 소유자의 실행 핸들을 쓰면 거절한다. 셸 전용 패널 IPC가 명시적 연결 때 이 팩터리를 호출한다. 기본 창은 첫 실행 안내 뒤 호스트를 연결하며, 모델 전송은 사람이 요청할 때만 시작한다.

1. **캡처:** 같은 창의 이미 불러온 지원 보기에서 `describe`를 받는다. 이 요청은 문서 버전·선택의 불투명 식별자·도구 권한의 상한·가리기와 변경 알림 지원 여부만 받고, skill이나 문맥을 만들지 않는다. 메인은 창·탭·편집기 instance·새 세대와 함께 캡처 식별자를 발급한다. 변경 알림을 지원하지 않는 실행기는 연결하지 않는다. ODT 등 실제 지원 도구는 실행 직전 준비된 세션에서도 다시 확인한다.
2. **참고 취득:** 캡처 식별자와 명시한 `document / selection` 범위를 전용 읽기에 넘긴다. 본문은 그때 처음 읽는다. 결과는 범위·버전·가리기 지원·잘림 표시를 가진 별도 snapshot이다. 참고를 위해 skill 문맥을 만들거나 다른 블록을 추가로 읽는 native 도구를 내놓지 않는다. 스냅숏은 저장 전 자료이며 디스크 fallback이나 자동 저장은 없다.
3. **대기열:** 사람이 보낸 요청은 캡처/참고 식별자만으로 대상을 고른다. 메인이 보관한 snapshot과 프로젝트 정체를 registry에 복사한다. 캡처는 최근 128개, 참고 snapshot은 최근 32개까지만 찾을 수 있고, 이미 들어간 요청은 자기 사본을 유지한다. 요청 하나의 참고는 20개·합계 200,000자 이내다. 넘으면 조용히 버리지 않고 거절한다. 창의 대기열 상한은 기존 32개다.
4. **준비·도구:** FIFO에서 하나를 꺼내 대상과 참고의 실제 버전을 재확인한 뒤 대상 skill만 준비한다. 반환하는 참고 자료는 명시적으로 읽은 범위뿐이다. 도구 호출은 소유 창·패널 세대·대화·실행·binding 번호, registry ticket, 실제 준비된 도구 목록과 선택을 확인한다. 다른 문서나 참고 문서에 대한 쓰기는 실행되지 않는다. 대상 쓰기의 검증된 답만 registry의 버전을 전진시키고, 같은 문서의 오래된 대기 요청은 중단한다. 실제 편집 직전 검사는 기존 편집기 어댑터가 계속 맡는다.
5. **변경·종료:** `workspace-ai:editor-event`는 호스트 정체와 준비/변경/해제만 보내며 문서 내용이나 경로가 없다. DOCX 본문, Markdown 본문·frontmatter·원문 모드·재읽기, HWP 플러그인 문서 변경을 전한다. 참고 변경이나 실행기 소실은 진행 중 요청의 중단 신호를 끊는다. 대상 도구가 낸 자기 변경은 검증된 답으로만 인정한다. 시간 초과는 타이머로도 발견하고, 실패한 편집은 재전송하지 않는다.
6. **취소 완료 대기:** 편집기에는 각 바인딩마다 별도의 무작위 실행 id를 준다. 대화나 패널의 run id가 나중에 재사용돼도 예전 정리 요청이 새 일을 끝낼 수 없다. `settle`은 그 실행의 준비·도구·응답 검사를 취소한 뒤 실제로 끝나야 답한다. 제어기는 이 답을 기다린 뒤 다음 요청을 준비한다. 다른 대화의 취소가 현재 실행을 해제하지 않는다.

제어기는 제공자·구독 프로그램·파일·공개 MCP·대화 저장소를 호출하지 않는다. 아래 실행 호스트는 기존 보내기 문지기·프로젝트 믿음/권한·transport를 주입받는 구조다. 기본 창의 호스트도 이 주입 자리에 기존 서비스를 연결한다. `onStopped`와 `signal`만 있는 현재 코드를 실제 구독 프로세스 종료 검증으로 해석하지 않는다.

## 대화별 상태와 기록 연결

`renderer/src/workspace-ai/conversations.ts`의 `WorkspaceConversations`는 출처별로 이력·초안·첨부·스킬 칩·대상·참고·프로젝트·스크롤·MCP 선택·대기 요청·허락·오류와 별도 실행기를 소유한다. 실행기는 호스트가 대화마다 한 번 만든다. 열기와 선택은 전송·중단·허락 승인을 하지 않으며, 같은 출처를 다시 열어도 실행기와 초안을 교체하지 않는다. 기존 기록의 제공자·모델이나 프로젝트 출처는 현재 설정·믿음을 바꾸지 않는다. 기존 첫 저장/이동 서비스가 돌려준 참조는 `rebindLegacy`로 갱신하며, 실행 중인 대화 id·실행기·초안·허락을 유지한다. 서로 열린 두 기록을 이 경로로 합치지는 않는다. 호스트는 기록할 때 이 최신 출처를 사용해야 한다.

사람이 보낸 요청의 입력은 대기할 때 복사한다. 콜백과 허락 답은 컨트롤러 instance·대화·실행 id·증가하는 실행 세대로 검사하며, 취소 후 같은 run id를 써도 옛 콜백은 거절한다. 취소/해제 시 답하지 않은 허락은 거절하고 해당 실행의 신호를 끊는다. 이 컨트롤러는 화면 상태의 소유자다. FIFO 순서와 편집기 취소 완료 대기, 모델 호출 전 보내기 판단은 메인 제어기와 호스트가 계속 맡는다.

`main/workspace-ai/conversation-history.ts`의 `WorkspaceConversationHistory`는 주입받은 기존 `ProjectStore`와 `ProjectChatStore`를 사용한다. 문서 기록은 안정적인 `projectId/chatId` 참조를 따라 읽고 쓴다. 프로젝트 기록은 기존 `openChat/append`를 거쳐 다른 PC 표시와 쓰기 거절을 그대로 전한다. 명시적으로 새로 만든 프로젝트 대화는 첫 답 전에 파일이 없어도 빈 기록/첫 메시지 버퍼로 열 수 있다. 프로젝트 쓰기가 막히면 로컬 대화로 대신 저장하지 않는다. 홈의 임시 기록은 창 세션과 대화 id로 나누고, `attachMemory`로 원래 홈 호스트의 읽기/쓰기 원천을 연결한다. 본문 복사·자동 병합·문서 닫기에 따른 기록 삭제는 없다.

이 부품들은 **셸 전용 패널 IPC와 기본 창의 호스트에 연결했다.** 실제 `AgentLoop` 두 개와 가짜 transport로 대화 전환 중 응답·이력 격리를 검사했고, 임시 로컬 저장소로 재시작 복원·크기 제한·잘못된 버전·기존 문서 첫 저장/이름 변경 후 기록 연결을 검사했다. 기존 프로젝트 기록의 전체 검사도 함께 통과했다. 실제 모델·사용자 문서·Windows 설치본 검증은 아니다.

## 공용 실행 호스트와 카드

`renderer/src/workspace-ai/run-host.ts`의 `WorkspaceRunHost`는 대화별 `AgentLoop`를 메인 실행 제어기에 연결한다. 명시적 전송의 초안·대상 캡처·참고 snapshot·프로젝트를 고정하고 FIFO로 실행한다. 모델에 내놓는 문서 도구는 준비된 대상의 목록뿐이다. 참고는 명시적으로 읽은 가린 snapshot과 범위·문서 정체·버전만 문맥에 넣고, 문서 디스크 읽기나 저장으로 대신하지 않는다. 실행기에는 대상 도구와 메인의 비동기 응답 검사를 그대로 호출한다.

보내기 판단은 `useAiSendGate.admit/admitQueued`와 현재 `gate`를 주입하는 자리다. 처음 붙잡힌 요청은 원래 `WorkspacePendingSend`를 `resume`으로 돌려주므로, 그사이 다른 대화를 고르거나 초안을 고쳐도 이전 요청의 대상이 바뀌지 않는다. 대기 중 확인/안내를 기다리면 요청을 유지하고 `wake` 때 다시 판단한다. 연결 불가면 중단하며, 준비 뒤에도 다시 판단한다. `prepare`는 기존 프로젝트 믿음·첨부·사용자 스킬·드라이브·인터넷/MCP 경계를 연결하는 필수 자리다. 반환한 프로젝트 id/문맥 버전이 대기 바인딩과 다르면 보내지 않는다. **이 주입 자리에 실제 기본 화면의 서비스와 구독 전송을 연결한 상태는 아니다.**

`WorkspaceRunCards.tsx`는 기존 `McpPermissionPrompt`를 쓴다. 대화마다 다른 허락 저장소를 유지하며, 표시한 대화만 바꾸는 것은 거절이나 승인으로 처리하지 않는다. 실행 중단·호스트 해제는 기다리는 허락을 거절한다. 표시 문구는 기존 21개 언어 자원을 사용하는 호스트가 넘긴다. 종료 시에는 편집기 작업뿐 아니라 이전 transport/루프의 취소 완료도 기다린 뒤 같은 대화의 실행기를 다시 쓴다. 기록 쓰기 실패는 화면에 남기고 재시도·로컬 대체 저장·모델 재전송을 하지 않는다.

전체 실행 되돌리기는 문서 내용을 패널에 보내지 않는다. `workspace-adapter.ts`가 첫 쓰기 직전 편집기 안에 스냅숏을 한 번 잡고 검증된 변경마다 버전을 전진시킨다. 편집기·메인은 최근 16개 토큰만 보관한다. 메인은 별도의 소유자/대화/실행/binding 토큰을 내주고, 실행이 끝난 뒤 같은 문서 인스턴스·버전·읽기 전용 여부를 확인해 복원을 한 번만 전달한다. 수동 변경·다른 문서·새 세대·재사용·실행 중 복원은 거절한다. DOCX는 기존 `rollback-snapshot.ts`와 같은 시점의 `DocsReviewStore` 목록을 함께 복원한다. 메모 해결·각주 글 수정처럼 본문 노드가 그대로인 변경도 되돌리기 카드를 만들며, 본문이 같으면 본문 트랜잭션을 만들지 않는다. 목록과 본문 중 하나라도 수동으로 바뀌면 복원하지 않는다. Markdown은 기존 본문/frontmatter `getSnapshot/restoreSnapshot`을 쓴다. HWP는 첫 쓰기 전 플러그인에 실행 취소 기록의 체크포인트를 두고 기존 studio 기록으로 요청 전체를 되돌린다. 별도 WASM 스냅숏이나 저장·재열기를 쓰지 않는다. 비동기 다리가 대기하는 동안 바뀔 수 있어 체크포인트 취득 뒤 버전을 다시 검사하고, 복원은 플러그인 안에서 문서 정체·버전·다른 변경 수·쓰기 가능 여부와 필요한 전체 기록을 같은 차례에 검사한다. 기록이 사라졌거나 첫 실행 취소의 스냅숏 예산 여유가 없으면 한 단계도 시작하지 않는다. 현재 엔진 상한 100개에서는 요청의 변경 묶음 97개까지다. 체크포인트도 16개까지만 두고 문서 교체·어댑터 해제 때 정리한다.

비동기 응답 검사를 위해 `AgentSkill.verifyResponse`는 Promise도 받을 수 있다. 기존 동기 검사는 같은 순서로 동작한다. 검사 중 취소는 루프를 끝내고 세대를 바꿔, 늦은 검사 성공/실패가 다음 실행을 건드리지 못하게 한다. 이 경로는 공통 실행부 전체 검사와 가짜 transport로 확인했다. 빌드한 앱에서는 저장 전 Markdown 자료로 DOCX를 고친 뒤 토큰으로 원래 본문을 복원했고, 다른 대화의 메시지와 원본 파일 세 개는 바뀌지 않았다. 실제 모델 호출은 0건이다.

## 공용 패널과 선택적 셸 배치

`WorkspacePanelController`는 기존 `WorkspaceRunHost.conversations`를 사용한다. 출처 목록 갱신·대화 선택·문서 초점 변경은 읽기나 전송을 시작하지 않는다. 새 대화의 최초 대상만 클릭 당시의 초점 문서를 제안하고, 기존 대화의 대상은 자동으로 채우지 않는다. 대상/참고 취득의 늦은 답은 대화와 동작 세대로 구분하며, 대상 변경 실패 뒤 이전 문서에 보내는 길은 막는다. 참고는 명시한 범위로 취득하고, 패널에는 본문 대신 식별자/바인딩만 전달한다. 이력 출처와 실제 `capture/reference/create` 서비스는 호스트가 주입한다. 셸 전용 IPC의 명시적 연결로 실제 서비스를 주입할 수 있다. 기본 창도 같은 서비스 주입 경로를 사용한다.

`WorkspacePanel`은 21개 언어의 대화/대상/참고 선택기, 초안과 스크롤 복원, 기존 작성기/허락/되돌리기 카드와 접힌 레일의 작업 중단을 그린다. 화면이 받는 실행 식별자는 복사본이므로 중단은 객체 참조 대신 컨트롤러·대화·실행·세대 네 값으로 검사한다. `AiComposer.sendDisabled`는 문서 바인딩이 준비되지 않아도 글쓰기는 허용하고 전송/대기열 추가만 막는다. 패널을 숨기거나 다른 대화를 선택하는 동작은 호스트를 해제하지 않는다.

실행 직전 목록과 인터넷 도구 스위치를 다시 읽고 기존 `createUserMcpSkill`을 쓴다. 완성된 문서/프로젝트/첨부/스킬/외부 도구 조합 전체에 `guardReceivedContent`와 `guardOutbound`를 씌운다. 받은 내용 지키기와 주소 허락은 같은 대화의 다음 실행에도 이어지며, 대화 중 설정을 꺼도 이미 받은 내용의 막기는 유지한다. 저장된 기록의 도구 이름·성공 여부는 보호 로직에서만 읽어 막기를 복원한다. 기록된 MCP 본문을 모델 이력에 새로 넣지 않는다. 현재 스킬의 MCP 필요 안내도 그 대화의 서버 선택을 따른다.

대기 허락 뒤에는 서버 끄기·도구 확인 필요·인터넷 스위치와 실행 정체를 다시 검사한다. 중단·완료·연결 해제는 해당 실행의 신호로 도구를 끊고 늦은 결과를 버린다. 늦은 주소 허락으로 다음 실행의 도구를 호출할 수 없고, 패널 해제는 목록/인터넷 변경 구독도 정리한다. 실제 서버 연결과 호출은 기존 main 허브와 preload만 사용한다.

## 드라이브 첨부와 실행 준비 (2026-11-05)

`drive-status / drive-pick / drive-check / drive-search / drive-read`는 공용 패널 전용 요청이다. 상태에는 연결·도구 사용 가능·학습 확인/무료 연결 통과 여부만 있고 계정·토큰은 없다. 고르기는 이미 연 대화에서 사람이 누를 때만 기존 Google 선택 창으로 진행한다. 고른 파일은 기존 첨부 등록·가리기 경로를 지나며 늦은 선택 답은 원래 대화의 칩과 안내에 붙는다. 기존 홈의 `KbAskPanel`에 `aiOfficeDriveAi`를 열지 않는다.

`main/workspace-ai/drive.ts`는 실행을 시작할 때 대상·참고의 main 소유 경로와 고정된 첨부 경로를 묶고, 도구 호출마다 패널 소유자·대화·실행·중단 신호를 확인한다. 기존 드라이브 서비스가 학습 확인·AI 읽기 허용·무료 연결 거절을 판단하며, 읽기 전후 같은 실행과 권한인지 다시 검사한다. 완료·중단·패널 해제 뒤의 답은 폐기한다. `WorkspaceRunPreparation.beforeTurn`을 전송 직전에 기다리고, 기다리는 동안 중단하면 늦은 확인 답으로 전송을 시작하지 않는다. 드라이브 사본/첨부/이전 읽기가 있는 대화는 각 모델 차례 전에 학습 확인과 무료 연결 상태를 다시 본다.

화면의 `WorkspaceDrivePreparation`은 대화별 `createDriveSkill`과 `guardDriveContent`를 사용한다. 자동 읽기 성공 뒤에는 전체 도구 조합의 외부 전송을 새 대화까지 막으며, 실패한 실행 뒤에도 이미 받은 내용의 막기는 유지한다. 저장된 기록에서는 성공 메타데이터만 보호 로직에 더하고 읽은 본문을 모델 이력에 복원하지 않는다. 검색·읽기 본문은 대화 파일에서 뺀다. 사람이 고른 첨부는 기존 정책처럼 외부 도구 차단을 만들지 않는다. 기본 창의 호스트도 실제 선택된 제공자와 main 실행 입구의 판단을 그대로 거친다.

## 보내기 문지기와 기존 AI 전송 (2026-11-05)

`useWorkspaceConnection`은 기존 `useAiSendGate`와 모델 선택기·연결 안내·첫 연결 안내·막힌 실행·사용량·입력 축소 부품을 선택적 호스트에 공급한다. 확인 중 붙잡힌 요청은 원래 대화의 대상과 초안으로 재개하고, 연결 불가면 초안을 남긴다. 대화 전환은 요청을 새 대화로 옮기지 않는다. 준비 뒤와 각 모델 차례 전에 같은 문지기를 다시 확인한다. 로컬 모델의 문맥 확인과 도구 미지원 판단도 기존 함수를 쓴다. 오류·사용량·입력 축소는 원래 대화에만 붙으며 연결 오류는 기존 연결 상태를 다시 읽는다. 다른 연결로 계속은 사람이 누를 때만 기존 설정 저장 함수를 거친다.

모델 차례는 전용 `stream / stream-cancel` 요청으로만 보낸다. main의 `WorkspaceStreams`가 실제 시작된 실행·전체 소유자·대화·바인딩과 하나의 진행 중 차례를 검사하고, 네이티브 대화 식별자는 main이 대화별로 발급한다. 화면이 보낸 제공자 설정은 쓰지 않으며 `streamWorkspaceAi`가 저장된 선택을 읽어 기존 `ai:stream`과 같은 `resolveAiRun`·실행 문지기·구독 사용량/입력 축소·중단 경로를 호출한다. 드라이브는 모델 진입 직전에도 검사한다. 중단·완료는 실제 전송이 끝나야 답하고 다음 실행도 그 종료를 기다린다. 패널 해제·본문 이동·렌더러 종료는 같은 중단 신호를 끊는다. 기존 편집기와 홈의 전송 입구는 그대로다.

이 연결은 기본 창의 `WorkspaceAppFrame`에서도 사용한다. `e2e/workspace-connection.spec.ts`는 합성 Markdown과 PC 안 가짜 OpenAI 호환 서버로 실제 메인 전송·사용량·중단·원본 보존을 확인한다. 외부 AI·실제 구독 호출은 0건이다. 실제 구독 프로세스와 Windows 설치본의 종료 확인을 대신하지 않는다.

## 기본 창의 호스트 연결 (2026-11-05)

`WorkspaceAppFrame`이 일반 시작 경로에서 첫 실행 안내를 마친 뒤 `useWorkspaceConnection`을 한 번 소유한다. 도움말 탭·독립 편집기·떼어 낸 창에는 설치하지 않는다. 탭 표시줄의 AI Assistant로 열며 첫 시작은 접힌 상태다. 접으면 예약 영역을 없애고 호스트·대화·초안·실행은 유지한다. 앱 표시 설정의 좌우·글자 크기·맞춤법·시작 설정을 재사용하고, 공용 패널의 마지막 열림만 셸의 localStorage에 별도로 기억한다. 기존 문서 패널의 상태를 옮기거나 덮어쓰지 않는다.

`WorkspacePanelReservation`은 예약 변경을 직렬로 보내고 main의 확인 뒤 같은 영역을 `AppFrame`·홈·구분선·패널에 공급한다. 크기·배율·분할·발표 변경은 main의 이벤트를 따른다. 작은 창의 임시 레일과 복귀는 저장한 열림 상태를 바꾸지 않는다. 옛 확인 응답·해제 뒤의 이벤트는 버리고, 실패한 연결은 탭 표시줄에서 사람이 다시 열 때만 재연결한다. 창의 연결 해제는 기존 중단·자원 정리 경로를 따른다.

현재 대상·참고는 HWP/HWPX·DOCX/ODT·Markdown/텍스트만 지원한다. 긴 글 작성기·빠른 작업 등이 남아 **기존 편집기 AI 입구와 홈 질문은 유지한다.** 공용 패널 하나로의 전수 이행 완료가 아니다.

## 연속 요청의 대상과 선택 갱신 (2026-11-05)

보내기를 누르면 그 순간의 글·첨부·스킬·참고 목록을 고정하고, main이 발급한 대상 캡처에만 `refresh`를 요청한다. 편집기는 같은 문서 인스턴스와 보관된 선택 핸들을 확인해 현재 버전을 돌려준다. 현재 커서로 새 범위를 고르거나 본문을 패널에 보내지 않는다. 갱신을 기다리는 동안 대상을 다시 고르거나 참고를 바꾸면 이전 보내기는 끝내며, 뒤에 쓴 초안·다른 대화·해제된 호스트에 늦은 답을 적용하지 않는다. 안내에 붙잡힌 요청과 이미 대기열에 든 요청의 바인딩은 다시 갱신하지 않는다.

DOCX와 Markdown은 기존 편집기의 선택 매핑을 다음 요청까지 보관하고, HWP는 기존 선택 토막과 실제 글자가 같은지 플러그인에서 검사한다. 첫 쓰기 전의 되돌리기 지점에는 유효한 선택 범위도 편집기 안에 함께 보관해, 복원 뒤 같은 핸들을 새 버전에 잇는다. HWP의 복원 버전은 실행 취소와 같은 동기 작업에서 반환한다. 수동 편집 등으로 선택을 더는 확인할 수 없거나 선택이 사라지면 재선택이 필요하다. 처음부터 선택이 없었던 요청은 새 커서를 가져오지 않고 선택 없음으로 남긴다. 참고 스냅숏과 이미 대기 중인 요청은 예전 버전에 고정되며 변경되면 기존 검사로 거절한다.

실제 DOCX·Markdown 편집기와 HWP 어댑터의 연속 편집·되돌리기·선택 이동·수동 변경, 메인의 문서 교체/대기열 고정과 잘못된 갱신 답을 단위 시험으로 검사했다. 빌드한 앱의 `e2e/workspace-hwp-undo.spec.ts`는 같은 대화에서 편집 → 전체 복원 → 재요청 → 연속 요청, 수동 변경 뒤 복원 거절과 HWP/HWPX 내보내기 바이트·원본 파일 보존을 확인했다. `workspace-default-host.spec.ts`도 통과했다. 둘 다 로컬 가짜 서버를 쓰며 실제 구독 호출은 0건이다. Windows 설치본 확인은 남았다.

## 워드 배치·스타일 저장소 (2026-11-05)

`DocsLayoutStore`는 App의 기존 쪽 설정·구역 목록·머리말/꼬리말 변형과 상속/편집 표·스타일 upsert·기본 글꼴·워터마크의 저장 대기 상태를 소유한다. 기존 화면과 두 AI 호스트는 같은 setter와 현재 값을 쓰고, 저장/복구는 현재 store 값을 읽는다. `ai/layout-access.ts`가 기존 읽기/쓰기 모델을 공유한다. 스타일 upsert를 복원해 비웠을 때 문서 CSS와 번호 스타일 표도 parsed 값으로 돌려놓는다.

공용 어댑터는 `set_header_footer`, `set_page_setup`, `insert_section_break`, `list_styles`, `define_style`, `set_watermark`를 기존 skill·ODT 필터로 제공하며 `apply_ops`의 스타일 적용도 같은 목록을 읽는다. 별도 상태 변경도 변경 횟수·문서 버전·대기 요청 무효화·전체 실행 되돌리기에 포함한다. 읽기 전용과 참고에는 쓰기 도구를 내놓지 않는다. 명시한 참고 읽기에는 머리말/꼬리말·스타일 목록을 덧붙이지 않는다.

첫 쓰기 전 본문·검토·배치 상태와 유효한 선택을 편집기 안에 함께 보관한다. 저장으로 parsed 기준이 바뀌면 옛 요청과 되돌리기를 거절하며, 기준이 같은 복원은 더티 표시까지 정확히 되돌려 원래 없던 저장 부품을 만들지 않는다. 공용 구역 나누기는 기존 삽입 경로에 `deferSave`를 주어 원본 자동 저장 예약을 만들지 않는다. 긴 글 작성기·빠른 작업·양식 저장·중복 AI 입구와 다른 형식의 이행은 별도로 남는다.

## 워드 대상의 양식 바이트 연결 (2026-11-05)

공용 제안 카드는 제안 당시 DOCX/ODT 대상의 문서 정체를 보관한다. 대화·초점·현재 대상 선택을 바꾸어도 이 정체를 바꾸지 않는다. `template`은 모델 도구가 아닌 패널·편집기 전용 요청이다. `info`는 이름·제목·가리기 여부만 읽고, `preview`와 `as-is`는 기존 `templateDocBytes`로 현재 편집 내용을 직렬화한다. 원본 파일 저장이나 디스크 저장본으로의 대체 읽기는 하지 않는다.

편집기와 메인은 읽기 전후 인스턴스·버전·본문 밖 상태를 검사하고 진행 중 실행·문서 교체·해제·늦은 답을 거절한다. 응답은 안전한 파일 이름과 기존 64MB 상한을 검사한다. `as-is`는 알려진 가리기 표시가 있으면 바이트를 읽기 전에 거절하고 직렬화 뒤에도 검사한다. 미리보기 사본의 이름과 가리기 판정은 같은 바이트 캡처를 따른다. 바이트는 모델 이력·대화 파일·메인 캐시에 보관하지 않는다.

양식 단추와 21개 언어 문구, 로컬 저장·비운 양식 사본 열기는 기존 공용 부품/서비스를 사용한다. 미리보기는 원래 대화의 카드에서 이어지고, 다른 대화를 보는 동안 끝나도 원래 출처에만 저장 표시를 남긴다. 다른 문서 형식·긴 글 작성기·중복 AI 입구의 이행은 남았다.

## 워드 긴 글 작성기 연결 (2026-11-05)

## 워드의 기존 AI 시작점 연결 (2026-11-05)

기본 창의 워드 리본·보기 메뉴·F7·검토/오른쪽 클릭 AI 작업은 `docs:workspace-ai-entry`로 같은 창의 준비된 공용 호스트에 연결한다. main은 실제 열린 DOCX/ODT 보기 객체·최상위 프레임을 확인하고 그 보기의 대상·선택을 먼저 캡처한다. 화면이 문서 경로나 탭을 지정하지 않는다. 호스트는 이벤트 구독 뒤 `entries-ready`로 수신 준비를 알리고 해제 때 닫는다. 패널/편집기 교체·닫기 중 늦은 캡처는 전달하지 않는다. 탐색만으로 문서 본문을 읽거나 모델을 호출하지 않는다.

명시한 빠른 작업은 새 공용 대화에 원래 캡처와 요청을 넣으며 기존 대화의 초안·참고·실행을 바꾸지 않는다. 기존 확인 절차와 `autoRun`을 보존하고 같은 보내기 문지기·FIFO·버전 검사로 실행한다. 공용 패널 안의 네 빠른 단추는 여전히 요청만 채운다. AI 창 열기·접기는 이미 고른 대화의 대상을 바꾸지 않는다. 연결 전·독립/분리 창·선택 편집 대기열은 기존 패널로 돌아간다. 수락한 요청은 다시 보내지 않으며 문서 교체 뒤 늦은 응답도 버린다. 아직 옮기지 않은 기능과 기존 초안을 위해 편집기 레일·호스트는 남긴다.

자동 검사: 편집기 입구 2건과 셸 소유/준비·늦은 답·대화/문지기·호스트 시험 41건이 통과했다. 빌드한 앱의 로컬 가짜 서버 e2e 2건은 리본 다듬기의 선택 편집·오른쪽 클릭 동의어·기존 초안 보존·보기 메뉴 접기/복귀·일반 호스트 수명·원본 바이트 보존을 확인했다. 실제 AI/구독 호출은 0건이다. Windows 설치본 확인과 나머지 형식의 시작점 이행은 남았다.

최종 회귀 확인: 워드 전체 4,108건 통과 후 샌드박스의 루프백 제한으로 실패한 Zotero 파일을 제한 밖에서 재검사해 5건 모두 통과했다. 셸의 작업 화면 267건·워드/셸 형 검사와 최종 빌드·변경 코드 lint 및 라이선스/규칙 검사가 통과했다. 변경 파일 서식은 통과하고 전체 서식 검사의 기존 `.omx/` JSON 5개 실패는 그대로다.

## 워드 선택 편집 대기열의 공용 실행 (2026-11-05)

선택 편집 표식과 카드는 기존 편집기가 소유한다. 보내기 클릭은 현재 문서 버전을 캡처하고 같은 표식의 현재 위치·가린 발췌로 기존 아래→위 묶음 지시와 화면 요약을 만든다. 메인은 실제 보낸 워드 보기의 문서 정체·버전·쓰기 가능 여부를 검사하며 마지막 선택은 제외한 캡처를 발급한다. DOCX 어댑터는 선택 핸들이 없는 요청을 문서 전체 요청으로 받아 실제 커서를 빌리지 않는다. 끝의 삽입 기준은 문서 끝이고, 마지막 블록이 그림이어도 선택으로 처리하지 않는다.

새 공용 대화가 초안을 설치한 뒤 한 번 쓰는 `entry-ack`로 인계를 확인한다. 메인은 원래 보기와 같은 문서·버전·쓰기 가능 상태를 다시 확인한다. 수락 뒤 인계 당시와 같은 대기 항목만 소비하며 그 사이 더하거나 고친 항목은 남긴다. 30초 제한·준비 해제·문서/보기 교체·응답 중단은 원래 대기열을 남기며 로컬로 재전송하지 않는다. 공용 호스트가 없는 독립/분리 창만 기존 실행으로 돌아간다. 실패 안내는 21개 언어이고 문서 교체 뒤 늦은 답은 버린다.

연결 차단은 기존 공용 문지기와 대화의 초안을 사용한다. 묶음의 블록 위치는 인계 당시 버전에 고정하고 일반 보내기의 버전 갱신을 하지 않는다. 이후 문서가 바뀌면 기존 실행 경계에서 거절하며, 대상을 다시 골라도 이전 묶음을 새 대상으로 보내지 않는다. 모델에는 기존 묶음 지시를 보내고 화면 메시지·대화 파일·되돌리기 카드에는 사람에게 보인 요약을 쓴다. 다른 대화의 초안·참고·실행과 원본 파일은 건드리지 않는다. 카드 UI 이행·만들기 전달·그림/매체·Windows 설치본 확인은 남았다.

## 워드 선택 편집 대기열 카드 (2026-11-05)

`edit-queue`는 모델 도구와 분리된 명시적 UI 연산이다. 같은 창의 공용 패널·대상 문서 인스턴스·세대를 확인한 뒤 현재 버전의 편집기에서 목록/수정/삭제/비우기/위치 찾기/보내기만 받는다. 응답은 대기열 버전과 최대 10개 항목(요청 500자, 현재 가린 발췌 160자, 표식 생존 여부)이다. 사라진 표식의 원래 발췌·문서 본문·블록 위치는 목록에 넣지 않는다. 조작에는 목록의 버전이 필요하며 문서나 대기열이 바뀌면 거절한다. 실행 중·준비 중의 조작도 거절한다.

`queue-changed`와 `edit-queue-changed`는 호스트/탭 정체만 알리고 본문·요청·위치는 싣지 않는다. 빈 대기열에는 본문 변경마다 목록을 읽지 않고, 목록 읽기는 대상 캡처를 추가 발급하지 않아 다른 대화의 캡처를 밀어내지 않는다. 화면은 대화·대상별로 카드 상태를 해제하고 늦은 답을 버린다. 카드는 기존 뷰·21개 언어 문구를 재사용하며 키보드로 위치 찾기와 행 동작을 사용할 수 있다.

선택 편집 추가는 `docs:workspace-ai-entry`의 `queue`로 그 문서의 공용 대화를 연다. 이미 같은 문서가 대상이면 기존 초안·참고를 보존한다. 카드의 보내기는 기존 `edit-batch`·`entry-ack`를 재사용하고, 원래 보기·문서·버전의 인계 확인 뒤에만 소비한다. 실패한 조작이나 중단된 답을 자동 재전송하지 않는다. 독립/분리 창은 기존 카드를 유지한다. 기본 창의 기존 레일은 나머지 기능 이행을 위해 남는다.

## 워드 일반 양식 사본의 요청 인계

`skills:take-handoff`는 기존 main의 일회 `SkillHandoff`를 먼저 꺼낸다. 프로젝트에 속하지 않은 DOCX/ODT 사본에 준비된 같은 창의 호스트가 있으면 내부 `template-handoff` 이벤트로 요청·칩·main 발급 캡처를 넘긴다. 편집기에서 보내는 `docs:workspace-ai-entry`의 허용 종류에는 이를 추가하지 않는다. 새 공용 대화의 초안·칩 설치와 같은 문서·버전의 `entry-ack`가 끝나야 편집기에는 소비된 요청(`null`)으로 답한다. 수락 전에는 모델을 부르지 않으며 30초 제한·해제·실패는 늦은 수락을 막은 뒤 기존 편집기에 요청을 돌려준다.

`WorkspaceUserSkills`는 그 대화의 인계 당시 문서 정체·버전·칩 id만 메모리에 둔다. 해당 칩은 이미 연 사본에서 실행하며 새 사본을 만들지 않는다. 보내기 직전 켜진 스킬과 현재 본문·크기·MCP 필요 여부를 기존 함수로 다시 검사한다. 다른 대상·대화에는 이 예외가 적용되지 않는다. 문서가 바뀐 인계의 최초 요청은 새 버전으로 갱신하지 않는다. 공용 보내기 판단·FIFO·보호·중단·기록·전체 되돌리기는 기존 호스트를 사용한다. 수락 응답이 끊기면 초안은 보존하되 자동 전송은 막는다. 프로젝트 사본의 문맥·완료 저장은 아래 후속 단계에 연결했다. 양식 비우기 미리보기는 카드 이행 전까지 기존 경로다. 공개 계약·파일 형식·원본 저장은 바꾸지 않는다.

## 워드 프로젝트 양식 사본의 요청과 완료 저장 (2026-11-06)

프로젝트 사본도 같은 일회 인계와 `entry-ack`를 사용한다. main이 사본의 프로젝트를 구해 `template-handoff.projectId`로 넘기고, 공용 호스트는 그 프로젝트에 새 대화를 만든다. 기존 프로젝트 준비·믿음·지침/기억·범위 도구를 실행 직전에 확인하며 기존 기록을 합치지 않는다. 공용 패널에서 양식을 여는 `open-template` 요청은 열린 대화의 출처로 프로젝트를 정한다. 셸의 마지막 프로젝트 선택을 대신 쓰지 않고, 같은 창의 가용 대상 탭에서만 하위 폴더를 구한다. 기존 양식 사본 열기와 배치 규칙을 재사용하며 프로젝트 없는 대화는 프로젝트를 물려받지 않는다.

인계 수락 때 main이 실제 열린 프로젝트 대화를 확인하고, 그 대화·캡처에 한 번 쓰는 프로젝트 저장 권한을 남긴다. 같은 캡처와 프로젝트로 들어온 첫 실행만 이 권한을 소비하며, 성공 완료와 편집기 정리 뒤 비공개 `save-project-copy`를 원래 사본에 보낸다. 다음 실행·되돌리기는 이 저장이 끝날 때까지 기다린다. 중단·실패한 실행에는 저장을 보내지 않으며 완료를 다시 요청해도 저장을 되풀이하지 않는다. 문서 인스턴스·최종 버전·쓰기 가능 여부·중단을 직렬화 전후 검사하고, 기존 `docs:save-into-project`는 고정한 프로젝트 id와 현재 배치가 같을 때만 쓴다. 기존 저장·프로젝트 쓰기 확인·겹치지 않는 이름을 재사용한다. 저장 거절을 다른 폴더로 우회하지 않고, 파일 바이트·저장 경로는 모델 이력이나 새 인계 이벤트에 넣지 않는다. 저장 뒤 이전 parsed 기준의 전체 되돌리기는 기존 저장 계약대로 거절한다.

양식 비우기 미리보기와 공용 호스트가 없는 독립/분리 창은 기존 경로다. 프로젝트 사본의 인계를 연결한 것으로 전체 편집기 이행이나 Windows 설치본 확인을 완료 처리하지 않는다.
